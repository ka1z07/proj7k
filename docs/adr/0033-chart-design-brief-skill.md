# 0033. 先写设计稿再落键：谱师 skill、分轨与长条

- **状态**：accepted（2026-10-18；Kai：「通过 agent 理解乐曲结构和动机给铺面设计给出标注，模拟人类谱师写谱时，先确定每段的音乐动机，再确定段落的主要技法和键形设计，最后进行一致性完善的过程；当前生成的铺面仍然非常僵硬，每个段落没有明确主题，大量切叠的混合非常公式化，而且我们还需要完善长条」）。八条决定都经 Kai 逐条确认。保留 ADR-0032 的节奏模型与 ADR-0031 的段落切分；取代 ADR-0031 第 3 条（段落键型倾向只是乘在概率上）。 **已被 ADR-0046 取代（2026-10-28，设计稿、分轨、每段一主技法与 chart-design skill 删除）。**
- **背景**：gen-4 的节奏已经从人写谱学，但每一行放什么键仍是按概率逐小节抽：同一段里楼梯、颤、叠轮流出现，没有主次；生成器跟的是所有起音的混合，而谱师每一段只跟一层（这段跟鼓，那段跟人声）。另外生成器只会写米键。

## 决策内容

1. **谱师是一个项目 skill，不进面板**（`.claude/skills/chart-design/`）。跑这个 skill 的 Claude Code 会话当谱师；面板的「谱面生成」不调用任何 LLM。Claude 听不到音频，它读的是生成器算出的特征：段落切分、各段各分轨的能量与起音、乐句重复关系，以及频谱图和能量曲线的图片。
2. **分工：Claude 写设计稿，生成器落键**。设计稿是一份 JSON，生成器读它，节奏模型落位置、键形模型落列，引擎闭环到目标星级。Claude 不逐键写谱：几千个键的对拍和星级正是生成器已经能保证的。
3. **音乐动机 = 段落功能 + 主跟层**。段落功能：前奏、主歌、铺垫、高潮、间奏、尾奏，决定强度和留白。主跟层：这一段的谱跟哪一层写（鼓、贝斯、人声、其他），以及要突出的节奏型。
4. **分轨**：生成器可选用 Demucs 把歌拆成鼓、贝斯、人声、其他四轨。面板「谱面生成」加一个实验选项，勾选后才下载模型与 PyTorch 并使用；不勾选时行为不变。分轨结果按音频哈希缓存。没有设计稿时，生成器每段自动选主跟层：这段里起音最清楚、与段落能量变化最一致的一轨；节奏模型读主跟层的起音，其他轨降权作背景。设计稿里写的主跟层覆盖自动选择。
5. **每段一个主技法，最多一个点缀**。主技法用引擎八个池的名字（`rc_jack`、`rc_tech`、`rc_speed`、`rc_stamina`、`ln_general`、`ln_tech`、`ln_inverse`、`ln_release`），设计稿与星级同一套词；键形写到具体型（如 `rc_jack` 下的「3+2 跳叠」、`rc_speed` 下的「楼梯」「切」）。主键形至少占该段七成的行；点缀只出现在设计稿标出的位置（如每 4 小节最后一拍、跟军鼓），不再每小节随机混。
6. **一致性完善**：生成器出谱后输出逐段审稿表与谱面预览图，Claude 按六条检查，不满足就改设计稿重生成，最多三轮：
   1. 同一乐句再出现时用同一键形；第三次起可镜像或加密做变化，但不换技法。
   2. 最难处落在高潮段，前奏、间奏不比高潮难。
   3. 每段密度起伏跟主跟层的能量走，没有动静处留白。
   4. 段落交界处不出现别手的大跳。
   5. 每段主键形占到七成，点缀只在标出的位置。
   6. 整张谱星级在目标 ±0.1 内。
7. **长条**：放在哪里、拉多长也从 Kai 曲库里的人写谱和音频学。节奏模型增加输出：该行是否长条、长度档（1/4、1/2、1 拍、2 拍、更长）；尾巴吸附到网格，倾向落在主跟层下一个起音或声音衰减处。设计稿每段写长条比例与类型；没有设计稿时按主跟层的延音程度自动定。第一版就做 `ln_general`、`ln_release`（长短参差）与 `ln_inverse`（反键：整段几乎全按住，在起音处松手再按，作为一种段落风格）；`ln_tech` 随数据能学到多少算多少。
8. **技法配比学人写谱**。一张谱不覆盖所有技法：在 Kai 曲库的人写谱上逐段跑引擎八个池的读数，统计一张谱用几种主技法、各占多少段、哪些技法常一起出现、主技法与段落功能的对应，存成先验。没有设计稿时生成器按这个先验给各段分配主技法；skill 把它作为参考给 Claude。

## 实现顺序

分轨 → 长条 → 技法配比先验 → 设计稿接口与 skill → 一致性审稿。版本号到设计稿接入时升为 `gen-5`。

## 后果

- 面板默认行为不变；分轨是可选的重依赖（PyTorch 数 GB，CPU 上每首 1–3 分钟）。
- 节奏模型要用带长条标签的数据重新导出、重新训练（在 meow 上跑）。
- 引擎不变，星级指纹与护栏不受影响。

## 实现结果（2026-10-18）

- **分轨**：meow 上实测，分轨约为歌长的 0.3–0.5 倍，之后读缓存。主跟层按各轨起音在混音起音尺度上的强度打分（只看各轨自己的尺度时几乎不选鼓）。
- **长条模型**：Kai 曲库 1171 张谱重新导出，去掉 37 张对不上位置的，1134 张训练（留出 149 张）。六档长度分类，留出 log loss 0.535，只按各档频率猜是 0.891。
- **技法配比先验**（按谱面星级分档，主技法按小节计）：
  - 低于 4★（223 张）：一张谱多用 1–2 种主技法，`rc_speed` 占 63%。
  - 4–7★（365 张）：多为 2 种，`rc_speed` 36%，`ln_general` 17%，`rc_jack`、`rc_tech` 各 14%，`rc_stamina` 10%。
  - 7★ 以上（546 张）：2–3 种，`rc_stamina` 20%，`rc_speed` 18%，`rc_tech` 17%，`ln_general` 16%。
- **第一次实写（Inorganic Dystopia，8th）**：审稿发现设计稿的强度只是给模型的出行概率乘个系数。模型判断稀的段落仍然稀，全曲重新缩放时还把它的行数分给了别的段，于是主 drop（强度 0.95）每小节只有 2–6 行，而强度 0.4 的过渡段有 12 行。现在每段按「有声时长 × 强度增益」单独分配行数（增益 2^(3(i−0.5))，0.35×–2.8×），1/8、1/6 小节也优先给强度高的段。审稿第 2 条改为每个高潮段都要压过非高潮段，而不只是最难的那一个。
