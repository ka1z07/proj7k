# 0030. 生成器的键型从人写谱里学

- **状态**：accepted（2026-10-17；Kai：「现在写的谱一点都不 human，没有人类玩家对铺面设计的特色」）。取代 ADR-0027 第 8 条（配键），其余不变。 **已被 ADR-0046 取代（2026-10-28，键形模型删除）。**
- **背景**：ADR-0027 的配键逐行选代价最低的列组合：躲开刚按过的列、平衡两手、按音高偏左偏右，再加一点随机。每一行单独看都合理，连起来却是「均匀乱撒」。拿线上曲库 400 张 ranked/loved 米谱，保留人写的节奏、只用旧配键重配一遍，对比原谱：

  | | 人写 | 旧配键 |
  |---|---|---|
  | 三个连续单键里的楼梯（c, c±1, c±2） | 20.8 % | 2.5 % |
  | 三个连续单键里的颤（a, b, a） | 8.4 % | 1.2 % |
  | 半拍间隔的叠键 | 24 % | 10 % |
  | 一拍内的键型与前面某拍相同（另有镜像） | 19 %（10 %） | 11 %（5 %） |

  旧配键把叠键当成纯代价，于是谱师有意写的叠、楼梯、颤都被躲掉了；节奏重复时键型也不重复。另一个问题在节奏层：同一段音乐再出现时，起音强度会有一点起伏，按阈值逐点选出来的节奏每遍都不一样，谱师却会写成一样的。

## 决策内容

1. **配键是一个从人写谱统计出来的模型**（`generator/patterns.py`）。一行是 7 位掩码。下一行掩码的概率取决于：押数、与前一行和前两行的间隔（毫秒分桶：≤55、75、95、120、150、190、250、340、500，以上算停顿，停顿前的行不再算上下文）、前两行的掩码。四级回退 n-gram，`(n, g1, r1, g2, r2) → (n, g1, r1) → (n, g1) → (n)`，Witten–Bell 插值。间隔用毫秒而不是拍：同样是 1/4 拍的叠，在 120 BPM 和 240 BPM 是两回事。
2. **训练数据是线上曲库里 ranked、loved、qualified 的全部 7K 难度**（5721 张；按 set id 每 10 个留 1 个做留出集，训练 5123 张），每张谱原样和镜像各算一次，模型没有左右偏向。长条只看头。重训：`PYTHONPATH=src python3 tools/train_pattern_model.py --db ~/.cache/proj7k/catalog.sqlite3`，模型存为 `generator/pattern_model.json.gz`（约 2 MB，最具体的两级丢掉出现不到 4 次的上下文）。留出集每行对数似然 −1.896（困惑度 6.66）。
3. **逐行按模型概率抽样**（温度 1）。每个网格点有自己固定的随机数，一行的增减不会改动别处的抽样；二分强度时星级因此随强度平滑变化。
4. **重复**：一段 4、2 或 1 拍的节奏（位置与押数）与前面 1、2、4、8 段之一相同时，按概率照搬或镜像那一段的键。4 拍 9 %/13 %、2 拍 4 %/5 %、1 拍 2 %/4 %（照搬/镜像；长段照搬已经包含短段，所以短段的概率小），定到三种段长上都与留出谱实测一致（人写：照搬约 7 %、镜像约 9 %；逐行抽样两者都约 1 %）。
5. **听起来一样的小节用一样的节奏**（`generator/phrases.py`）。网格点记下所在拍、小节与小节内位置；二分还是三分改为按小节决定（逐拍决定会被噪声翻来翻去，同样的小节网格不同就没法比）。小节按三段起音强度向量比较，余弦相似度 ≥ 0.85 并入前面最像的组（网格布局不同的不比，太安静的小节不动）；组内按出现顺序每至多 2 个小节一段。选点之后，同一段里每个位置：多数小节有音符就全都有（押数取多数），否则全都没有，只保留比组内这个位置的平均强度高 0.35 以上的（加花、镲）。最初试的是逐点平均强度再选点，但真实歌曲里同一乐句的起音强度起伏太大，只有一成小节能这样对齐。
   - 一段的节奏一起变，星级随强度成台阶上升，台阶可能跨过目标；二分结束仍在容差外时，在台阶两侧再试至多 8 种由种子派生的配键抽样（配键本身也会改变星级），取最接近的。
6. 版本号 `gen-2`。评测（`python3 -m proj7k.generator.evaluate`）额外给出人写谱与生成谱的键型统计（`patterns.pattern_stats`：楼梯、颤、半拍内叠、节奏重复时键型也重复、整小节节奏重复）。

## 后果

- 在留出谱上保留人写节奏、用新配键重配：楼梯 23 %（人写 24 %）、颤 7 %（9 %）、半拍内叠 24 %（27 %）；节奏重复时键型照搬/镜像在 1、2、4 拍段上都落在人写的 ±2 % 以内。
- 模型从数据里学，叠键不再被硬性避开：低星目标里也会有人写谱那样的叠，星级闭环用更少的音符补偿。没有硬性的最快叠键限制（`PatternSampler.min_jack_ms` 留着，默认关）。
- Kai 曲库 40 首（每首一个难度，用人写谱的 timing 和星级）第一版评测：星级误差中位 0.055★；键型统计中位（人写 → 生成）楼梯 0.216 → 0.162、颤 0.060 → 0.105、半拍内叠 0.044 → 0.041、节奏重复时键型也重复 0.092 → 0.086、整小节节奏重复 0.262 → 0.079。最后一项促成了第 5 条从「平均强度」改为「选点后多数表决」；第二轮（一段至多 4 小节）：整小节节奏重复 0.438、节奏重复时键型也重复 0.173，都过头了（人写 0.262 / 0.092），精确率 0.692、召回率 0.863、星级误差 0.061★。按三首歌上的比例改成一段至多 2 小节。第三轮（定稿）：整小节节奏重复 0.280（人写 0.262）、节奏重复时键型也重复 0.159（0.092）、楼梯 0.165（0.216）、颤 0.104（0.060）、半拍内叠 0.048（0.044）；精确率 0.694、召回率 0.860、星级误差中位 0.066★，40 首全部落进目标。颤偏多、键型重复偏多留待 Kai 试打后再调。
- 已知差距：高星金属、速度类歌曲里人写谱更多用半拍和弦叠（Xing Noises 人写半拍内叠 0.30–0.38，生成 0.02），生成器偏向用 1/4 切来堆星级。这是选点层的问题（每行几个音、走哪种细分），要从带音频的人写谱学。
- 引擎不变，星级指纹与护栏不受影响。
- 仍未做：长条；按音色分层（底鼓、军鼓、旋律各走固定的手）；选点本身也从人写谱学（需要带音频的数据）；谱师风格。
