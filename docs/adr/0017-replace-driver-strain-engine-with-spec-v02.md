# 0017. 以规格 v0.2 取代旧难度引擎 (Replace the Driver/Strain Engine with Spec v0.2)

- **状态**：accepted（2026-10-02 与项目方对齐；实施在分支 `engine/spec-v0.2`，分片见 ADR-0018）。取代 ADR-0015、ADR-0016，以及 ADR-0002 中「以 Jinjin 段位星级作为技法标尺」的部分；Jinjin 7K Dan 作为难度梯度共识的部分仍然有效。
- **日期**：2026-10-02
- **背景**：
  旧引擎是「驱动层 + 应变层」双系统：8 条原始驱动各自经按技法标定的映射得到技法星，总星为其最大值（ADR-0016），另有一条应变时间序列（P90 / Top5% 池化）服务 profiler、downscaler 与仪表盘。它的问题是机制与标尺互相缠绕：驱动层读数与应变层读数会分歧（#56）、逐轴锚定律让八个轴各有一把尺（#55）、驱动排不出自家阶梯时靠逐技法补丁修（#53），而且每一次修补都在同一批 120 张基准谱上选定，没有独立的验收。
  规格 `osu-mania-7k-difficulty-spec.md`（v0.2）把问题重写为单一的事件需求累积：每个事件有物理需求 `v_i`，经手累加器得到 `d_i`，总难度 `D` 与八个技法难度 `D_k` 由同一个求解器在不同的隶属权重下解出，主导度 `π_k` 由归因给出。原型 `prototypes/prototype_spec_v01_engine.py`（默认即 v0.2）已在 120 张基准谱上跑通，单张约 0.04 秒。

## 决策内容

1. **以规格 v0.2 的引擎取代旧链路**（`features`、`strain`、`radar`、`rating`、`difficulty`）作为 A 组（总星数）与 B 组（八技法标量）消费者的评分来源。规格是唯一依据。
2. **新引擎的公开输出就是规格 §9.6 的结构**：总难度与星数、八个技法的 `D_k` / 星数 / 覆盖 / 主导度、`dominant_skill` 及排序与间隔。不提供旧字段（`raw_star_rating`、`drivers`、`strain_profile`）的兼容层。八个技法名一律改为 `rc_jack`、`rc_tech`、`rc_speed`、`rc_stamina`、`ln_general`、`ln_tech`、`ln_inverse`、`ln_release`；旧 `stream` 与新 `rc_stamina` 同名不同义（前者是串，后者是和弦串）。
3. **验收以规格 §14 为准，而不是以旧闸门为准**：T3、T4、T5、T6、T10、T11 写成测试并通过；外部 `practice_maps/` 的难度检验（16/19 在 ±1 段内）在测试里复现。**T1（段池严格单调）未通过**，v0.2 在八个技法阶梯上有 12 处倒挂，以 xfail 加逐池棘轮记账，不当作验收（ADR-0018）。
4. **常数是先验，未校准。** 规格 §13 的校准在 v0.2 上做过，T2（留一段）不通过，判为过拟合，不采用。所有阈值与三项结构改动都选自同一批 120 张谱，没有同含义的留出集；唯一的外部检验显示难度泛化、主导技法标签不泛化。主导度的评分用 T11（对受控改动的响应），槽位标签 T9 只作诊断（项目方 2026-10-02 裁定）。
5. **C 组（时间序列）与 D 组（旧应变单位）不在本次替换内**，留在旧引擎模块上另行设计（ADR-0018）。

## 放弃的路

- **统一应变场提案**（`docs/specs/unified-strain-field-engine-proposal.md` 与对应原型，未入库）：更早的一版单一应变场设计，已被规格 v0.2 取代，不作依据。
- **在旧双系统上继续逐技法补丁**：#53、#55、#56、#45 的前提在新引擎下全部失效，不再有对应机制。
- **规格 §13 的校准**：见决策 4。
- **保留 `--spec v0.1` 路径进生产**：生产只留 v0.2；v0.1 由冻结的原型文件复现（打 tag）。
- **兼容层**（保留 `evaluate_intrinsic_difficulty` 并按旧字段名回填）：没有任何新值能诚实地对应 `drivers` 与 `raw_star_rating`，且会把 `stream` / `rc_stamina` 的语义差别藏起来。

## 后果

- 总星、技法星、主导技法的数值与旧引擎不同，星级指纹、锚点区间、`dan` 段位表需要重基线化（两步提交：先换引擎并看新阶梯，再重基线化）。
- `current_engine_version()` 会变化。`lazer/daemon` 据此重新评估并改写已注入谱面的难度名与标签，这是对用户游戏库的写入，因此接入被放在最后一片，且先有 `--dry-run`（ADR-0018）。
- 旧引擎在 C、D 组消费者删除之前继续存在，产品里同时有两套星数标尺，靠标注区分。
