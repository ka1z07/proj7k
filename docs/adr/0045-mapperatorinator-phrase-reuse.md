# 0045. Mapperatorinator 的乐句复用与分段接力

- **状态**：accepted（2026-10-26；Kai：「现在 mappertorinator 生成的铺面设计上并不连贯」，读完结论与两个方案后：「都做」）。
- **背景**：meow 上对比了 Kai 最近生成的 YONEDA – KAERU、快速与顺序模式的 LIMBO / nightcore 样本和人谱（ADR-0040 之后）：
  - **模型本身不复用乐句。** 人谱 LIMBO 有 39% 的 8 拍乐句在别处原样或镜像再出现；模型写的谱一律 0%，顺序模式也一样。它每个窗口只看前约 8 秒，副歌第二遍不记得第一遍。小节之间的衔接和人谱相近（连贯度 0.45 对 0.46）。
  - **快速模式每 8.19 秒一道接缝**：每个窗口从零写起，接缝处叠键大小的变化是 0.75–0.87，其他地方约 0.55，顺序模式和人谱没有这个差别。
  - 降难让叠键略碎，补写只在整窗空白时显著，两者都是次要的。

## 决定

1. **乐句复用（`generator/reuse.py`）**：按 timing 把歌切成两小节一句，每句与前面布局相同的句子比两样东西：每拍的音高分布（chroma，80–4000 Hz）和三频段起音强度。两样都至少 0.9 相似时，用前面那句的音符（按拍对齐，长条照抄）覆盖这一句；被覆盖的句子还可以再当后面句子的来源，所以副歌出现三次也只写一遍。安静的句子不动。只看起音不够：流行歌的鼓点让每句的起音都很像，合成测试里不同旋律的两句起音相似 0.96，chroma 只有 0.41。
   - 每次生成后、评星与降难之前做（补写之后），默认开启：命令行 `--no-model-reuse` 关闭，面板「乐句复用」勾选项。
   - 阈值 `SIMILAR = 0.9` 先按合成歌定，在 meow 上用带音频的人谱校准：复用到的句子里人谱也重复的比例（准确率），以及人谱重复了但没复用到的比例。
2. **快速模式分段接力**（`generator/mapperatorinator_patch.py`）：安装时给固定版本加一个 `generate_chains`（`parallel_chains=8`）。窗口按它的顺序模式切（每步约 1.6 秒），分成 8 段首尾相接，每段内部按顺序、每个窗口都读前面写过的音符，8 段的同一步放进一个批次一起解码，所以耗时约是一段的长度。第一段之后的各段也从上一段停笔的地方接着写（保留 lookback，只是前文为空）。接缝只剩段与段之间的 7 道。它自己的 `parallel=true` 和 ADR-0040 的重叠窗口补丁（`parallel_keep`）不再使用；旧补丁打过的源码会先还原再打新补丁。
3. **整段单点**（Kai：「现在经常出现生成的一个段落每行只有单点是为什么」）：meow 上 110 次生成、37 次补写里，157 段 4 秒以上的「每行一个音符」，77% 是长条：模型在密集段用长条时，写成一串 1/4 拍的短长条，一次一列（KAERU 上 65 ms，229 BPM 的 1/4 拍），整段没有叠键。补写与降难不会制造它；长条比例真的传 0 的那几次（LIMBO、nightcore）一段都没有，而面板选「不出长条」时 0 被当成「没设」，没传给模型，它就自己放了 11–22% 的长条。修法：
   - 面板把长条比例照实传给模型，「不出长条」就是 `hold_note_ratio=0`。
   - 每次生成后，4 秒以上、每秒至少 8 行、每行只有一个长条的段落，用局部重写（`hold_note_ratio=0`）再写一次，每次生成最多 3 段（补空白另算）。
   - 短于 0.3 拍的长条一律改成单点。

## 后果

- 降难在复用之后，删音符不按句对齐，重复的句子可能删得不一样。
- 人谱复用率因曲而异（KAERU 的人谱只有 1%），所以复用只在音乐真的重复时触发，不强求比例。
