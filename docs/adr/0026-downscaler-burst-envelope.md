# 0026. 降阶器的爆发上限：不留小段爆发与单轨锁指

- **状态**：accepted（2026-10-09；扩展 ADR-0021 与 ADR-0025 的降阶器；引擎未动）。
- **背景**：Kai 反馈降阶生成的练习谱有的「虚低」：问题处留着小段超难度爆发，高 BPM 下某些轨道被连续高负荷锁指连打。
  - 原因在引擎读数的形状。事件的读数 `d_i` 是所在手的累加器（§6.1，`tau_h = 4 s`），总星级是这种读数的软分位数：它读的是**持续**负荷。一秒的爆发只抬它一点；一根手指被连打而同手其他手指闲着，也会被同手的平均抹平。实测：220 BPM 1/4，同样的音符密度，七轨均匀滚动与「第 2 轨每隔一个音符就打一次」的星级几乎相同（3.71★ 对 3.66★）。
  - 对真实谱这套读数是标定过的（段位阶梯成立）；但降阶器是在**对着这个读数做优化**：删哪个音符最能压低 4 秒均值，就删哪个。压低均值最便宜的办法是把爆发周围削薄、把爆发留下。另外，候选打分用 `p(1-p)`，读数远高于目标的音符 `p ≈ 1`，边际收益趋于零，最难的那段反而最少被删。
  - 实测 120 张标杆谱降到 2nd：与同星级真实谱比，最忙一轨的连打速率中位高 20%，三成多超过真实谱的第 90 百分位，最高 2 倍；手的半秒峰值最高 1.5 倍。

## 决策内容

1. **两个短时读数，都取自引擎自己的量**（`downscaler/burst.py`）：
   - `hand`：引擎的手累加器，记忆从 4 秒缩到 0.5 秒（同样的 `v^γ`）；峰值就是全谱最难一小段有多难。
   - `column`：每一轨自己的累加器（记忆 1 秒），只喂同指速率 `j`（§4.1）；峰值就是一根手指被要求持续连打多快。
2. **上限是同级真实谱的包络。** 在 120 张标杆谱上拟合 `ln(峰值) = a + b ln(D)`，上限取拟合线加残差第 90 百分位：同一级别十张真实谱里九张不超过的程度。常数写在 `burst.ENVELOPES`，`tests/test_downscaler_burst.py` 用语料重拟合核对。
3. **闭环先削爆发。** 每一轮，只要练习谱在目标级别 `D*` 上还有读数超过上限，这一批就从超限的音符里挑（超出比例 × 该音符的 `v`，越难越先），仍走骨架保护、双手平衡、技法闸门与过冲减半；超限的音符删不动（骨架保护或闸门不允许）时退回原来的按星级选删。收敛条件是星级进入容差**且**爆发在上限内。
4. **仍超限就明说。** 结果里带 `initial_burst` / `final_burst`（峰值与上限之比，≤ 1 为同级正常），命令行报告多一行「Burst / Column vs cap」，控制台结果卡多一项「爆发 / 单轨负荷」；最终仍超限时给出警告，说明这张练习谱比它的星级难。
5. **原谱已在目标以下时不动它**：那时的爆发是原谱自己的，不是降阶造成的。

## 后果

- 标杆谱降到 2nd（只追难度）：手的半秒峰值超过同级第 90 百分位的比例从 29% 降到 6%，最大超出从 1.54 倍降到 1.16 倍；米谱的单轨速率基本回到上限内（最高 1.02 倍）。删除比例不变（平均 44%），星级仍落在目标容差内。
- LN 谱（尤其 Inverse、Release）的单轨读数常仍超限：放手后立刻再按同一轨是这类技法的本体，剩下的多是骨架保护的音符，此时按第 4 条给出警告。
- 先削最难的段也让保留技法模式走得更远：一些原先被技法闸门挡住的谱现在能保留技法降到目标（如测试里的 290 BPM chordjack）。标杆谱降到 0th 时提示改用只追难度的有 20 张，只追难度全部降到目标容差内。
- **引擎没有改。** 星级对短爆发与单轨不均的不敏感仍在，真实谱上同样存在；要在星级本身体现，需要改引擎常数并按 CLAUDE.md 的两步提交重标定（星级指纹、段位表、四档区间、棘轮）。这里只保证降阶器不去利用它。
