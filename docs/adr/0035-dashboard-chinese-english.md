# 0035. 控制台与桌面端的中英双语

- **状态**：accepted（2026-10-20；扩展 ADR-0024 / ADR-0034）。
- **背景**：Kai 要给桌面端（即 7770 端口的控制台，ADR-0034）加中英双语。页面一直只写中文，文字散在十个页面的静态 HTML、页面脚本拼出来的句子，以及后端返回给界面的报错、产物名和提示里。

## 决策内容

1. **中文仍是源文字，英文是一张对照表。** 页面照旧用中文写；`static/i18n.js` 里的 `EN` 把每句中文映射到英文。脚本里的文字一律写成 `tr("中文 {x}", { x })`（带占位符，英文可以调整语序），不再用模板字符串拼中文；静态 HTML 的文字与 `title` / `placeholder` / `alt` 在页面加载后按整句（空白折叠成一个空格）查表替换。英文放不下的个别标签（顶栏页签）用 `data-en` 给一个更短的英文。没有对照的中文原样显示，不会出错。
2. **语言怎么定**：第一次打开按系统 / 浏览器语言（`zh*` 用中文，其它用英文）；顶栏右侧的「English / 中文」按钮切换，选择存在 `localStorage`（外壳与各页面同源共享），切换后整个外壳重新载入。正在运行的任务在后台照常跑完，只是重载后的页面不再跟着显示它的进度，所以有任务在跑时先确认。
3. **后端消息跟着页面语言。** 页面把语言写进 `p7lang` cookie；`/api/me/*` 按请求的 cookie、WebSocket 按连接握手时的 cookie 设定当前语言（`proj7k.i18n`，一个 `ContextVar`），任务记下发起它的页面的语言，在工作线程里用它。会显示在界面上的消息在抛出处写成 `tr("中文", "English")`：控制台的报错与产物名、osu!lazer 启停、生成器的警告与报错、Demucs 安装与分轨提示、音频解码报错。命令行、日志里的诊断文字和测试不受影响，默认仍是中文。桌面端启动失败的弹窗按系统语言。
4. **测试兜底**：`tests/test_dashboard_i18n.py` 读每个页面和 `app.js`，断言脚本里的每段中文都包在 `tr()` 里且有英文、模板字符串里没有中文、静态 HTML 的每段中文都有英文、英文里没有中文且占位符一致；`tests/test_dashboard.py` 断言带英文 cookie 的连接收到英文报错，其它仍是中文。

## 后果

- 加新文字时要同时加一条英文对照，否则上面的测试会失败；这是有意的。
- 数据本身（谱面标题、艺术家、玩家名、技法与段位名）不翻译；技法与段位本来就是英文名。
- 实时雷达页（`live/static/index.html`，也是 OBS 叠加层）本来就是英文，只有拖放提示多一行中文，英文模式下去掉这行。
