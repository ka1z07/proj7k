# 0044. 同指项加权与按列平衡的降阶

- **状态**：accepted（2026-10-24；改引擎常数，扩展 ADR-0017/0018；改降阶器，修订 ADR-0011 的双手平衡、扩展 ADR-0021/0026）。
- **背景**：Kai 反馈两件事：密度集中在少数几列时引擎给的难度偏低；降阶后各列的密度强度不均，和原谱的列分布不一致。调研结论（项目文件 `column-concentration/` 里有复现脚本）：
  - **引擎**：瞬时需求 `v = j + x + o`（§4）。异指项 `x` 的时间尺度 `Δ0` 取局部行间隔中位数的一半，邻指上一行刚按过就贡献约 `0.8 κ × NPS`，所以 `x` 跟着整张谱的速度走；同指重复只按 `1/Δt` 线性计一次。结果是同样的音符密度，音铺得越开读得越难：20 NPS 的 40 秒单音流，七列轮流 5.91★，只用四列 4.66★，两手各一列（每指 10 Hz）4.77★。在真实谱的节奏上把音集中到两列，最忙手指的负担变成 2.5 倍，星级只变 ±0.1★。120 张标杆谱的有效列数全在 6.5–7.0，段位阶梯测不出这个偏差。
  - **降阶器**：48 张标杆谱降到 2nd，中指两列（第 2、6 列）的保留率只有全谱平均的 0.74–0.76，第 3、4 列是 1.18–1.34；列占比 L1 偏移中位 0.20。两个原因各占一半（消融验证）：删除收益正比于 `v²`，而 `κ` 让中指的 `v` 天然最高、拇指最低（各列平均收益 1.03/1.23/0.93/0.61/0.97/1.22/1.03）；骨架保护在每个和弦与小节重拍上固定保留最靠近第 4 列的音。

## 决策内容

1. **引擎：按下事件的同指项加权** `k_same = 1.75`（`engine/params.py`，`engine/demand.py`）：`v = ω (k·j + x + o) c`，按下 `k = k_same`，松开 `k = 1`（松开的 `j` 是面条长度，不是手指重复）。隶属用的同指份额 `r = j/(j+x+o)` 不加权，§8 的阈值是在它上面定的。
   - 取值：扫 1–3。2.0 的阶梯最好（τ 0.969），但第 5 段锚点残差 +0.267，超出 `anchors.json` 的 ±0.25；1.75 为 +0.249，在容差内，阶梯为 τ 0.967。取 1.75。
   - 这是对 v0.2 原型的第一处偏离。原型常数保留为 `params.V02`，`tests/engine/test_engine_golden.py` 在它下面继续核对移植（星数用金标准自带的 `a`、`b`）。规格的修订记录记为 v0.2.1 第 8 项。
2. **按两步提交重标定**：先改常数、确认阶梯，再重基线化：星标尺重拟合为 `STAR_A = 0.17277`、`STAR_B = 1.01923`（仍是 Zenith 不等式锚点生效）；`dan_table.json`；星级指纹；`guard.OWN_SKILL_RATCHET` 中提升了 LN Tech 与 LN Release 的棘轮；`burst.ENVELOPES` 在新读数上重拟合。
3. **降阶器：删除收益按列归一**（`pruner._per_column`）。收益只在同一列内比较哪个音更划算，不再跨列比较，`κ` 的列偏向不再决定删哪一列。
4. **降阶器：列平衡取代双手平衡**。打分除以 `retention_c ^ -COLUMN_BALANCE`（`COLUMN_BALANCE = 1`），`retention_c` 是该列相对原谱的保留率除以全谱保留率（`pruner.column_retention`）。保留得比全谱多的列先删，删得多的列受保护。目标是原谱自己的列占比，不是绝对的 50/50，所以原谱的左右手比例也一并保住。`BimanualFluxBalancer` 仍用来报告 `bimanual_flux_ratio`。
5. **骨架锚音不偏向中间列**（`skeleton._select_skeleton_anchor`）：面条仍优先；其次保留 `column_weight` 最低的列（降阶时传入各列保留率，即目前被删得最多的列）；最后用与列无关的确定性散列打破平局。
6. **一个音卡住验收不再停下**：批次减半到只剩最佳一个音、而它单独删除仍不过验收时，把它放到一边，用批次剩下的音重试，最多 8 次（`SKIPPED_BLOCKERS`）。主导技法边际很小的谱以前会在第一个候选上就停。

## 后果

- **引擎**：120 张阶梯总星级平均 τ 0.957→0.967、ρ 0.989→0.991、倒挂 11→9；八个池的自有技能阶梯无一变差，LN Tech τ 0.962→0.981，LN Release 0.829→0.867。20 NPS 两列（每指 10 Hz）读数从低于七列 19% 变为高 12%；220 BPM 1/4「第 2 列每隔一个音」从与七列滚几乎相同变为高 0.7★（4.10 对 3.37）。
  - 仍有的局限：同手的热列与闲列仍由手累加器平均，四列交替（每指 5 Hz）仍略低于七列（D 26.5 对 29.4）。若要更彻底，下一步是把 `burst.py` 的列累加器搬进引擎 `d_i`，或让 `Δ0` 跟手指自己的节奏挂钩；都需再做一次两步重标定。
  - 标杆谱里没有列集中的谱。Kai 提供公认「比星级难」的列集中谱后，宜加入外部留出检验（只检验、不参与拟合）。
- **降阶器**（48 张标杆谱降到 2nd）：各列保留率的中位都在 0.99–1.00，P10–P90 在 0.94–1.06；列占比 L1 偏移中位 0.20→0.03（最大 0.33→0.05）；高密段最忙手指占比的升幅从 ×1.30 降到 ×1.12。保技巧模式达标 41→43/48，只追难度仍为 48/48。
- `tests/test_downscaler_on_the_field.py` 的用例 Regular Stream Zenith→7th 改为 Stellium→7th：重加权后该谱的 Stream/Speed 主导度边际在降阶途中翻转，被技法闸门挡住（只追难度可达）。
- 所有星级都动了：120 张标杆谱中位 −0.11★，31 张变动超过 0.3★。上升最多的是 Regular Jack 高段（+0.35～+0.38★）；下降最多的是 LN 高段（LN General Stellium 12.14→11.13，LN Release Zenith 10.61→9.96）。LN 四池按段中位数更贴近 LN 共识锚点（Zenith 10.47→9.94，锚点约 10；10th 7.97→7.62，锚点 7.5–8），规格里记的「LN 高段偏高」因此减轻。
- lazer 里写入的星级与段位名需要重新同步；引擎版本号自动变化，旧的标记结果会被识别为过期。
