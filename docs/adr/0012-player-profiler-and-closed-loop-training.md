# 0012. 玩家回放诊断画像、应变响应模型与闭环训练架构 (Player Profiler & Closed-Loop Training)

- **状态**：accepted
- **日期**：2026-09-18
- **背景**：
  作为 proj7k 本地工具链的最后一步，系统需要通过玩家实际回放（`.osr`）数据提供客观的游玩诊断、水平评估与技法训练方向推荐。
  根据 [ADR-0001](0001-decouple-intrinsic-difficulty-from-player-data.md)，铺面固有难度必须与玩家游玩表现数据绝对解耦，玩家数据仅用于个人能力画像与训练反馈；同时根据 [ADR-0003](0003-cloud-platform-with-local-analyzer.md)，本地分析工具需深入微观击键时序与长条尾放精度。
  因此，需要确立一套在不破坏固有难度纯客观性的前提下，利用谱面时序应变曲线精准解构玩家击键病理、评估 8 维能力、并与降阶器（[ADR-0011](0011-closed-loop-strain-downscaler-and-technique-preservation.md)）及本地/云端曲库实现自适应闭环训练的系统架构。

## 决策内容

1. **两级分层诊断与时间视窗限制 (Two-Tier Architecture & Temporal Windowing)**：
   - **单局微观诊断 (Micro-Play Diagnostic)**：以单个 `.osr` 为输入，对准具体谱面的时序键形，输出各轨离散度、判定偏差漂移、致死段落归因及关键病理。
   - **全局宏观画像 (Macro-Profile Aggregate)**：玩家水平随时间动态演进，宏观画像显式支持双时间视窗：
     - **滚动近期状态 (Recent Rolling Form)**：滑动截取近 30 天内的有效对局，反映玩家即时竞技状态与活跃短板；
     - **历史巅峰画像 (All-time Peak Profile)**：聚合全历史对局中各技法维度的极限承压表现，刻画玩家的理论能力上限。

2. **应变-误差响应模型与段位能力映射 (Strain-Error Response Model)**：
   - 杜绝基于总分/Acc 的粗暴经验拟合，将玩家每个击键的时间偏差 $\Delta t_{\text{hit}}$ 与谱面对应时刻的 8 维微观瞬时应变 $S_d(t)$（来自 `proj7k.strain`）点对点对齐。
   - 沿应变梯度构建响应曲线，精确定位击键标准差 $\sigma$ 剧增且断连簇集的临界拐点，求得玩家在各技法维度上的**有效承压上限 (Effective Strain Capacity)**。
   - 将有效承压上限通过权威段位质心与星级标尺映射为玩家当前的 8 维技法雷达段位（如：Jack 7th Dan, Tech 5th Dan）。

3. **四维微观生物力学与读谱病理诊断 (Micro-Pathology Diagnostics)**：
   - **左右手与各指离散度失衡 (Bimanual & Inter-finger Asymmetry)**：统计各轨 UR 与平均偏移，量化双腕力量偏载及中指-无名指腱间剪切负荷；
   - **原位停滞疲劳漂移 (Jack Stagnation Drift)**：在长连叠击打中拟合时间偏移的回归斜率，量化耐力衰退与肌腱痉挛趋势；
   - **LN 释放精度与粘键倾向 (Release Window Bias & Hold Stickiness)**：解耦长条按下（Head）与释放（Tail）判定窗，区分提前放手恐慌与粘键延迟病理；
   - **级联断连前驱定位 (Cascade Failure Precursor)**：检测断连前 200~500ms 内的键形特征（如括号相变或负空间倒错），归因诱发知觉崩塌的根因。

4. **因果时序判定与多模回放摄入 (Causal Hit Matching & Dual Ingestion)**：
   - **因果时序判定 (Causal Hit-Window Matcher)**：严格模拟音游判定因果律，按时间先后在音符判定窗口内单向消费按键事件；在判定窗外或空轨处产生的无效敲击标记为**惊慌鬼键 (Panic Ghost Tap)**，用于量化恐慌性乱打程度，不污染正常判定分布。
   - **双模输入**：支持独立 CLI 接收本地 `.osr` 文件，以及通过 `proj7k.lazer` 守护进程与游戏日志监听实现对局结束后的自动化即时捕获。
   - **脏数据清洗**：剔除时长 $<30$ 秒或完成度 $<50\%$ 的重试（Retry）对局；对中途暴毙（Failed）对局保留其致死前高应变样本用于测定承压上限，但不计入稳定性基线。

5. **双教练模式与两阶段曲库推荐 (Coaching Modes & Beatmap Recall Hierarchy)**：
   - **教练策略**：支持以攻克晋级瓶颈为目标的“短板突破模式 (Bottleneck Breaker)”与面向特化型选手的“长板专精模式 (Specialty Push)”。
   - **推荐源策略**：
     - **严禁段位考题推荐**：坚决不从 Jinjin Dan 考级考题中推图，杜绝玩家应试背谱带来的感知失真；
     - **本地优先召回**：第一阶段优先扫描玩家本地已安装的曲库（通过 `client.realm` 技法标签与星级索引），精准匹配其承压上限附近的优质练习谱面，实现即点即练；
     - **云端按需推荐**：第二阶段留待 Web 云端平台就绪后，直接通过 Web API 检索全网与目标技法难度完美对齐的候选曲目。

6. **致死段落三阶梯靶向降阶练习包 (Three-Tier Targeted Practice Bundle)**：
   - 当诊断出特定致死段落（Fatal Pattern）时，自动提取其前后节奏缓冲时窗（前 10s 至后 5s），切出**局部高能切片 (High-Strain Section Slice)**。
   - 联动 `proj7k.downscaler` 闭环生成三阶梯衍生练习包：
     - *Recovery 档*：降阶至玩家当前稳定承压上限，用于重建 98%+ 准度的肌腱与读谱信心；
     - *Bridge 档*：介于当前上限与致死强度之间的中继过渡档；
     - *Push 档*：维持原谱难度的原汁原味局部攻坚切片。

7. **轻量持久化与多身份隔离 (Lightweight Persistence & Identity Isolation)**：
   - 在本地建立轻量 SQLite 档案库（`~/.proj7k/profiler.db`），根据 `.osr` 头信息中的玩家用户名与 ID 自动分档隔离。
   - 仅持久化每次对局的特征向量、时序偏差统计与时间戳，不存储原始高频按键流，保持极小体积并支持毫秒级时序窗口聚合。

## 权衡与取舍 (Trade-offs)

- **为什么采用应变-误差响应模型而非传统 pp / Rating 计算公式**：
  传统 pp 或 rating 公式是基于最终总分或 Acc 进行黑盒拟合，完全无法解释一张混押谱中玩家究竟是因为连叠（Jack）耐力不够掉分，还是因为长条（LN）乱放手掉分。应变-误差响应模型将击键动作精确落入微观物理应变场中，揭示玩家在具体生理负荷下的性能衰退拐点，具备第一性原理的因果解释力。
- **为什么坚决不从段位考级曲目推荐，而是本地优先召回**：
  段位曲（Dan Maps）是作为权威衡量标尺而存在的基准，如果玩家在日常练习中反复刷段位原曲，会导致背谱肌肉记忆取代真实的视奏反应与技法能力，甚至形成错误的动作定势。推荐本地常规曲库不仅贴合玩家日常打图习惯，也让已安装的大量优质曲目得到充分利用。
- **为什么因果时序判定中引入惊慌鬼键（Panic Ghost Tap）过滤**：
  高难读谱崩塌时，玩家常见反应是在所有轨道盲目乱按（Mash / Panic）。若采用全局时间规整算法，这些乱敲会被强制错位匹配给后面的音符，导致后续原本正常的击键全部被假阳性误判为严重偏移。因果窗口内消费、窗口外归类为鬼键的处理方式，最大化保障了后续分析的基准可信度。
