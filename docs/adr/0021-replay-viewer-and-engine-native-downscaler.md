# 0021. 复盘查看器与按新引擎重设计的下缩器

- **状态**：accepted（2026-10-05；承接 ADR-0020）。

## 一、复盘查看器

1. **形态：单个自包含 HTML。** `python3 -m proj7k.profiler -r X.osr -b X.osu --view [out.html] [--audio a.mp3] [--open]`。谱面、判定、按键帧与难度曲线序列化成一份 JSON 嵌进页面（`profiler/replay_view.py` + `profiler/static/replay_view.html`），浏览器端自己播放：无服务进程、无网络、无外部依赖。没走 live 的 websocket：复盘是离线、可分享、可存档的东西，而 live 守护进程的前提是 osu! 正在运行。
2. **下落式对齐，线上是谱面、线下是你的游玩。** 判定线以上是即将到来的谱面，以下是同一条时间轴上已发生的事：音符按判定着色（MAX/300 淡化，200/100/50/漏 逐级醒目，漏拍画 ✕），玩家实际按键画成从按下到松开的白条（按下点偏离音符中心的距离就是误差），空轨乱敲是紫色菱形，长条尾放的判定画在尾帽上。判定线下方的接收器随回放按键点亮。底部是命中误差尺（最近 4 秒）。回放只画 `t ≤ 当前时刻` 的按键，拖动时间轴不会剧透。
3. **难度时间线 = 引擎的难度场。** 柱高是该时间段内最大的 `d_i / D`（1.0 是谱面自身的定级水平，虚线），柱色是承载这段风险的技法，白线是 `Σ p_i`（以谱面水平游玩的期望丢失），方框是 8 秒窗口里风险最集中的 5 个难点（`ChartField.hot_spots`），其下红柱是玩家在该段丢掉的准度（`1 - 判定分/300` 之和）、紫点是乱敲。红柱落在高柱下，就是「死在了难处」。
4. **时间线可拖动到任意时刻**（指针捕获，拖动期间暂停、松手恢复），悬停读数，键盘 ←/→ 秒级、`[` `]` 在失误间跳、`H` 跳到下一个难点；URL 的 `#t=毫秒` 直接打开到某一刻。侧栏：八技法等级（来自 ADR-0020 的容量读数，标出「崩盘」）、难点列表、失误列表（可只看漏拍），均可点击跳转。
5. **时钟。** 载荷里一切时间都是歌曲时间（毫秒），与回放帧和音频同一个钟；DT/HT 下引擎在物理时间里读谱，载荷构造时按倍率换回。有音频时以 `audio.currentTime` 驱动并按 `速度 × 倍率` 设 `playbackRate`，没有音频或加载失败则退回静音的挂钟；音频以相对路径引用、不内嵌。
6. **验证。** `tests/test_replay_view.py` 钉住载荷与引擎场的守恒（风险和、最大读数、丢失和）、DT 下的时间换算、页面脚本的 JS 语法（`node --check`）与不可被 `</script>` 截断；`tests/replay_sim.py` 是按引擎自己的 `p_i(θ)` 打谱的模拟玩家，同一夹具也用于演示页面。

7. **从某一刻起练。** 页面的「Practice from here」把播放头所在时刻拼成 `--bundle --fatal-time` 的完整命令（回放与谱面路径已写进载荷），可复制；静态页面不执行命令，也不开本地服务。

## 二、下缩器

下缩链整体搬到引擎的难度场上（`engine/` 包本身未动，版本令牌不变）。

1. **闭环直接对着引擎星级收敛。** 引擎的星级每轮都能精确重算（一次求解约 0.06 秒），所以不再有「用应变选窗口、用星级判到达」的两套尺：目标是引擎星级（`--target-dan` / `--target-sr` / `--target-d`，三者落到同一个星与它的 `D*`），到达判据是该星级自上而下进入容差。`--target-strain` 与 `star_rating_to_strain` 退出下缩器（后者只因旧 `strain` 模块还在 import 而留在 `mapper`）。
2. **峰窗是「损失密度」窗，不是「读数超过 D* 的事件」。** 实测 D 可以高于全谱最大的 `d_i`：D 是「近顶事件的**质量**碰到容差」的位置（软分位数）。所以峰窗取 1 秒窗口里 `Σ p_i(D*) / 事件数` 超过总容差允许速率的那些。
3. **候选按一阶边际收益排序。** 每手的累加器对事件的 `v^γ` 是线性的，期望损失对它的导数有闭形（`downscaler/marginal.py`，`G` 的反向指数递推，O(n)）：`dL/d(v_j^γ) = (1-φ_r) G_r`，`c_i = β p_i (1-p_i) / (γ d_i^γ)`。它与删掉单音符后重算引擎得到的实际损失降幅的秩相关 ≈ 0.8–0.87，按它挑出的 40 个音符比随机 40 个多降 2–3 倍的损失（`tests/test_downscaler_on_the_field.py`）。排序时按该音符上主导技法的归属份额 `a_ik` 打 0.35 的折（不是不可动），再除以双手不对称惩罚。
4. **批量按引擎校正。** 每个峰窗取前 15–25%（ADR-0011 的范围），整批试删：技法保持闸门不过就减半；删过头（星级掉到目标容差下沿以下）也减半；单音符总是接受。结果是星级落在目标上而不是低于它。ADR-0011 的不变量（纯删除、骨架保护、双手流量、双闸门）不变。
5. **主导度并列不算变技法。** 双闸门第一道的「主导技法守恒」改按 §9.4 的主导份额读：仍是第一，或与第一名相差不超过 `DOMINANCE_TIE = 0.03`，都算守恒。实测 Regular Stream Zenith 的 `rc_stamina` 与 `rc_speed` 只差 0.04，裸 argmax 的判据让这张图在第四轮后就无法再删。
6. **练习包三档是引擎星级。** `profiler/coach.generate_targeted_practice_bundle`：Push 是切片本身的星级，Recovery 是 `min(stars_of(Θ), 0.8 × Push)`（Θ 是 ADR-0020 的玩家水平；没有水平时取 0.7 × Push），Bridge 居中，两个低档都由下缩器收敛到各自的目标星级。致死点前 500 ms 的主导技法由场给出（`CascadePrecursor.skill`，承载期望损失最多的技法），旧的和弦步形态标签（bracket / chordjack …）继续并存、不再喂练习包。
7. **留在旧引擎的**：`validator.compute_radar_cosine_similarity`（取旧 `TechniqueRadar`，已不被流水线调用）、live 的 `legacy` 键、批量工具的旧指标。它们随旧引擎一并删除。
