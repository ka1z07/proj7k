# 0039. 生成谱段落间密度收窄

- **状态**：accepted（2026-10-22；Kai：「现在铺面生成器生成的难度差异太大了，简单地方不应该过于简单，而且排的不应该这么稀」）。补充 ADR-0032（节奏模型）与 ADR-0031（按段落分配密度）。
- **背景**：没有设计稿时，每个位置出不出行由节奏模型按起音强度给概率，全曲再按目标行数统一缩放（`_scaled` 还先把概率 1.5 次方锐化）。安静的主歌起音弱，被排得很稀；而星级由最难的段落决定，于是到了目标星级，简单段几乎没东西可打。

## 决策内容

1. **每 4 小节一段重新分配行数**（`rhythm.pick` 的最后一步，`_evened`）。设一段每有声秒的期望行数为 d，改为 c·d^`CONTRAST`，c 让全曲（有设计稿时为设计稿每段）总行数不变；段内仍按模型概率的比例分。`CONTRAST = 1` 与原来完全一样，0 时各段一样密。
2. **默认 `CONTRAST = 0.5`**。有设计稿时只在设计稿每段内部收窄，段与段之间的强度照设计稿写（设计稿的强度是谱师有意的起伏，审稿也检查它）。
3. 评测统计增加 `density_floor` / `density_peak`（每 16 拍音符数的 P10、P90 除以中位数）、`rows_per_s`、`notes_per_s`，汇总增加同星级下生成/人写的 `notes_ratio_median`、`rows_ratio_median`；`evaluate --contrast` 可对比。版本号 `gen-6`。

## 评测（meow，40 首留出曲，人写谱的 timing 与星级）

| | 人写 | 1.0（原） | 0.5 | 0.25 |
|---|---|---|---|---|
| 星级误差中位数 | | 0.049 | 0.037 | 0.046 |
| density_floor | 0.51 | 0.55 | 0.66 | 0.71 |
| density_cv | 0.32 | 0.28 | 0.23 | 0.20 |
| 音符数 / 人写 | 1 | 1.03 | 1.07 | 1.09 |
| 行数 / 人写 | 1 | 1.12 | 1.27 | 1.35 |

0.5 时最简单的 10 % 段落从中位数的 55 % 抬到 66 %，同星级的音符多 4 %、行数多 13 %，星级误差最小。0.25 再往下收益变小，单键行已比人写多三成。

## 后果

- 比人写谱更平：人写谱的 floor 中位数 0.51，有几首（Rude Buster、Diminitive、Noiseful Imaging）低到 0.12–0.18，生成的这类歌会少一些大起大落。这是 Kai 要的方向。
- 同星级下密度只能涨到一定程度：再密，星级就要靠更少的叠和押来压住，那是键形的事，不在本次范围。
