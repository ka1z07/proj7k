# 0020. 难度场：新引擎里的「应变」，与 C/D 组消费者的重新设计

- **状态**：accepted（2026-10-05；承接 ADR-0017/0018/0019，回答 ADR-0019 留下的「C/D 组：单一应变场里什么是应变」）。
- **背景**：ADR-0018 决策 4 把 profiler 响应层、pruner 闭环、`p90_strain` 一族、live 应变画布留在旧引擎，因为新引擎「不输出时间序列」。实际上它每个事件都算一个读数 `d_i`（规格 §7）：事件在水平 θ 下以 ½ 概率丢失的 θ。总难度 D 与八个 D_k 都是对这组读数求解得到的。「应变」不需要另造量，就是它。

## 决策内容

1. **应变 := 事件需求读数 `d_i`，沿时间展开。** 两个派生量随它走：`p_i = p_i(D)`，事件在谱面自身水平上的丢失概率（期望丢失 = Σ p_i）；`s_i = p_i(1-p_i)` 的归一化，即 §9.4 的主导份额。时间线的「难」是 `d_i / D`，风险是 `Σ p_i`，承载它的技法是 `Σ a_ik p_i` 的最大者。代码在 `proj7k/field.py`（`ChartField`），**放在 `engine/` 包之外**：引擎的版本令牌摘要包内每个模块，消费者不能让已注入的谱面失效。
2. **玩家容量 := 把引擎的方程反过来读。** 引擎定义 D 为 `Σ w_i p_i(θ) = ε (W + N0)` 的根。玩家在技法 k 上的水平 Θ_k 取 `Σ w_ik p_i(Θ) = Σ w_ik ℓ_i + ε_k N0` 的根，ℓ_i 是该事件实际的准度损失（`1 - 判定分/300`：300g/300 为 0，200 为 ⅓，100 为 ⅔，50 为 ⅚，漏为 1；LN 尾放单独判，窗口 1.5 倍，头未命中则尾为 1）。性质：丢失率恰为容差 ε 的玩家，Θ 恰等于谱面的 D_k；一个不丢的玩家高于它但有限（N0 先验质量）；旧响应层里的 sigmoid 拟合、分箱与「胜任门控」整套退场，没有新常数。星级是同一把尺 `stars_of(Θ)`，段位取 `dan.estimate_canonical_dan`。只算实际打到的事件（中途暴毙的回放不把没打到的算作丢失）。
3. **暴毙峰值 := 致死点前 1 秒内、技法 k 的隶属加权 `d` 的最大值**，换成星级后与 Θ_k 一同进入聚合。语义与旧版一致（暴毙时承受的读数是容量的下界证据），单位换成新尺。
4. **旧快照不混算。** 旧引擎写下的 `match_snapshots` 行，容量单位是旧星级，回放本体不在库里，无法重算。聚合只用带 `summary.engine = "v0.2"` 的行，其余计入 `legacy_excluded` 并在报告里写明；行本身不动、不删。
5. **下缩闭环直接对着引擎星级收敛。** 新引擎的星级可在每轮精确重算（一次 `evaluate_notes`），不再需要「窗口用应变选、星级判到达」的两套尺。目标星级经 `d_of_stars` 换成目标 D；候选音符由 `d_i > D*` 的事件挑出，按它们在 D* 的丢失概率与技法归属排序。详见 ADR-0021（下缩重设计）。
6. **复盘查看器是自包含的 HTML。** `profiler` 把谱面、判定、按键帧与难度曲线序列化成 JSON 嵌进单个页面，浏览器端自己播放；不经 websocket、不依赖 live 守护进程。详见 ADR-0021。

## 后果

- ADR-0018 决策 4 里「C/D 组留旧引擎」被本条取代：`profiler/response.py`、`aggregate.py`、`storage.py` 的应变换算、`coach` 的练习包、整条下缩链都迁到场上；旧 `radar`/`strain`/`rating` 仍留在原地，只剩 live 的 `legacy` 键与批量工具的旧指标在用。
- 容量单位变了：`MacroProfile`/`MatchSnapshot` 里的 `effective_capacity` 现在是等效 Hz（Θ），不再是旧应变；`star_rating` 是新星级。
- 前述「T1 倒挂」不受影响。
