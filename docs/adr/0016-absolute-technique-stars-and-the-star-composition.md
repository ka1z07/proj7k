# 0016. 绝对技法星级与总星级合成 (Absolute Technique Stars & the Total-Star Composition)

- **状态**：accepted（工单 #50 实施；**两条验收线未达成**，见「开放问题」，不得当作已达成）
- **日期**：2026-09-23
- **背景**：
  #47 把 8 个驱动改对、#52 把驱动层判别量落地之后，8 条驱动各自能排序本维阶梯（tech 0.790/0.921 与 ln_inverse 0.790/0.900 除外，见 ADR-0015）。但**分值仍是相对份额**：`SR_k = SR_base · (r_k / max r)^exp`，`SR_base` 是 P90 应变的锚定律值。由此：**主导维分值恒等于 `SR_base`**（份额为 1），8 维里没有一维有自己的值——一张 0 段谱与一张 Stellium 谱的主导维读数是同一条 `SR_base` 曲线，维度之间的比较也只是「谁占的份额大」。#44 要的是**绝对技法星级**：一个维度该说「这张谱的速」「有多难」，单位与 canonical 段位阶梯同一把尺。

## 决策内容

1. **8 个技法分值改为逐技法绝对锚定律：`SR_k = a_k · r_k ^ exp_k`，每个技法一套 `a/exp`。**
   锚定律的家族取自应变侧同一条（`SR = a·S^exp + b`），**截距 `b` 固定为 0**：驱动的零就是该维的零（`radar.compute_raw_technique_drivers` 在纯米谱上把 LN 四维精确清零，`tests/test_radar.py` 钉着这条），而带截距的拟合等价于「没有这一技法的谱也有 `b` 颗星」，会把雷达的零底整个抬起来。保留零底后 `a` 与 `b` 本来也不可分别辨识（`a·(r/b_ref)^exp` 是同一族），剩下的参数就是增益与指数。
   *实测代价*：自由截距能多买 1–2 张落带/轴（jack 11、tech 10、speed 12、stream 14、ln_general 13、ln_tech 13、ln_inverse 10、ln_release 14），代价是每条轴的零读数变成 `b`（2.6–3.7★）。

2. **总星级取 (α)：8 个绝对技法星级的最大值**（`synthesize_star_rating`），`p_norm` 与 `damping_coeff` 两个字段随之删除。
   工单给的次序是 (β) p-norm 优先、(α) 兜底，并明写「不要在 (β) 上反复调参硬凑」。**实测 (β) 不达标**，两次测量都指向同一结论：
   - 用逐轴最优锚表（本 ADR 记录 3 的「本工具」列）：四档锚点中位 **0th 4.514（带 [3.0, 4.0]）、5th 6.045（[5.0, 6.0]）、10th 8.359（[7.0, 8.2]）、Stellium 10.718（✓）**，**三档出带**；
   - 用本 ADR 选定的锚表：(β) 下四档中位 3.828 / 5.796 / **8.796（[7.0, 8.2] 出带）** / 11.059，且**总星级只有 43/120 落带（(α) 下是 77/120）**。
   damping 项原本就是「多面手加成」：在份额语义下它是相对形状的一部分，在绝对星级上它只是给每个谱白送 0.3–1.0★（`power_sum ∈ [1,8]` → 因子 1.0–1.28）。故按工单退 (α)，并把两个旋钮一起删掉（它们不再被任何算子读）。
   **实现口径的一处精确化**：工单写「总星级 = 主导维分值」，实现是 **8 个分值的最大值**（`max(radar.to_vector())`，即 p-norm 的退化端）。两者在 59/120 张谱上不同——驱动的 argmax 轴不一定是分值最高的那轴（见开放问题 2），而那些谱的 `synergy_bonus`（`SR_norm - dominant_score`）就是这个差。字段名沿用旧名，但它已经**不是**「协同增益」而是「最高分与主导维之差」，改名会动元数据契约（下游逐圈抄写），留作 #46 一类的工作。

   `aggregate_p_norm` 本身保留：profiler 的**玩家侧**总星级仍用它（`PLAYER_AGGREGATION_P_NORM` / `PLAYER_AGGREGATION_DAMPING`，家在 `profiler/aggregate.py`），只是 `p` 与 `damping` 改为必填参数、不再是引擎选项字段——它们不移动任何谱面的星级，不该进引擎指纹。

3. **`dominant_technique` 仍是原始驱动的 argmax**，`dominant_score` 是该维的绝对技法星级。
   这一维的语义是「这张谱是拿什么铺的」（驱动在算子自己的单位下比大小），下游按它判技法是守恒的（`downscaler.validator` 的主导维不变门禁、本维命中率、诊断断言），#50 不改它。**代价（未解）**：绝对星级下分值的 argmax 与驱动的 argmax 不必一致，见「开放问题 2」。

4. **技术锚表是标定常数**：家在 `calibration.StrainStarCalibration.technique_anchors`（8 条 `TechniqueStarAnchor`），`RatingOptions.technique_anchors` 有同名字段，随引擎指纹移动版本。

## 开放问题（未定，不得实施）

1. **±8% 落带在参数化标定族内不可达**（本 ADR 记录 3 的表）。票主裁定「接受边界 / 加宽标定族」，**加宽一条已按三种形状实测**，结果如下（票主据此可再定）：
   - **锚点插值**（在 0th/5th/10th/Stellium 四个 tiers 的实测驱动上做 log-log 插值）：**更差**，8–14/15；且梯形外推会爆（ln_general 的 10th↔Stellium 两结点靠得太近，Stellium 以上外推到 47★、Zenth 47.42 对 9.7）。
   - **单调结点曲线**（结点星值自由、单调约束）：能逼近上界 15/15，但结点间距一大一小就让区间外斜率失控（实测出现 `math range error` 级的外推），**即「把 15 个点拟合了事」的具体代价**——而外推区间正是玩家铺面所在。
   - **两段幂律（一个膝点，4 参数，两侧都是幂律因此外推行为正常）**：jack 10 / tech 10 / speed 11 / stream 13 / ln_general 13 / ln_tech 12 / ln_inverse 10 / ln_release 14 —— **仍只有 3/8 达标**。
   结论：**±8%/≥13 这条线在「不是把阶梯制表」的前提下达不到**，因此按 (a) 接受边界并写进 CI；要真正达标只剩 (c) 动驱动层（speed/jack 低端形状、jack 0th/1st 倒挂、tech/ln_inverse 的 Ω_irreg）。

2. **跨维可比性（绝对星级的固有代价，未解）**：每轴独立标定后，同一条分值序列在不同轴上不再保序——实测**本维主导 80/120**（驱动侧 89/120），选定表下 1 条 `*_alignment_diagnosis` 期望因此翻红：
   - `LN Inverse 8th`：`ln_inverse` 5.56 ≤ `ln_release` 6.03（驱动侧 inverse > release，仍成立）。
   另 2 条（`Regular Tech Stellium`、`Regular Stream Stellium` 被判给 speed）是 #52 已量化的 Ω_irreg 分辨力问题，与本票无关。
   **这条断言未改**：改它等于替票主回答「绝对星级允许不允许跨维翻转」，而工单明写「两份验收标准同时铆死时，先确认哪一份是本票真正要的」。
   *（记录：选定表把另外两条 `LN General 5th` 与 `Regular Jack 1st` 自愈了——因为选择目标里含「本维主导」这一项；单看逐轴最优拟合时它们会翻红。）*

3. ~~**全库验收线被本次切换压低**~~ **已裁定并落地（票主：「可以放宽」）**：Phase 2 的 `mean ρ ≥ 0.98 / mean τ ≥ 0.94 / 倒挂 ≤ 20` 实测为 **mean ρ 0.9816 ✓ / mean τ 0.9255 / 倒挂 22**，故 `mean τ` 与倒挂上限重基线为 **0.92 / 24**（余量口径同逐技法闸门），`mean ρ` 不动。原因是星阶梯的序现在来自**逐轴驱动**（τ 0.79–0.96），切换前主要来自**应变阶梯**（密度序，ρ 0.968–0.989）；`guard` 里记着旧值（0.94 / 20，实测 0.940 / 16）。

4. **米侧/长条侧的既有未决项不受本 ADR 影响**：ADR-0015 的 `tech` 0.790/0.921、`ln_inverse` 0.790/0.900 仍在红线下方（`tests/test_driver_ladder_gates.py` 双向钉住）。

5. **两处下游在「星级不再锚在应变上」之后需要各自的改动**（票主裁定「再作更改」；两处都是设计级改动，本 ADR 只记形态，动手前需定做法）：
   - `downscaler/mapper.star_rating_to_strain`（`mapper.py:80`）：把目标星级反解成 `target_strain`，剪枝循环以它为收敛判据（`pruner.py:145`）。合成改成 max(绝对技法星级) 之后，这条反解不再描述任何真实谱面，而剪枝器会照常「收敛」、测试也不会响。
   - `strain.compute_8d_strain_timeseries`（`strain.py:810+`）：把雷达维分值当星级输入、反解锚定律成应变，用于 profiler 的玩家能力雷达。它消费的雷达量级已从「份额」变成「绝对技法星级」，`tests/test_engine_literal_registry.py` 给它的 EXEMPT 理由（「在星级评级下游」）本就写错（见 #51 交接 §4.7），现在比例尺又换了一把。
