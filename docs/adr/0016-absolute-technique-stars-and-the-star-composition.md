# 0016. 绝对技法星级与总星级合成 (Absolute Technique Stars & the Total-Star Composition)

- **状态**：accepted（工单 #50 实施；**两条验收线未达成**，见「开放问题」，不得当作已达成）。**工单 #44 收尾复核（2026-09-23）**：四条决策逐条复核通过；未达成的验收线**移交 #53**（见「开放问题」1，驱动侧红线见 4；#49 见 5），复核另更正了两处数字错误与一行过期记载——见「收尾复核」
- **日期**：2026-09-23
- **背景**：
  #47 把 8 个驱动改对、#52 把驱动层判别量落地之后，8 条驱动各自能排序本维阶梯（tech 0.790/0.921 与 ln_inverse 0.790/0.900 除外，见 ADR-0015）。但**分值仍是相对份额**：`SR_k = SR_base · (r_k / max r)^exp`，`SR_base` 是 P90 应变的锚定律值。由此：**主导维分值恒等于 `SR_base`**（份额为 1），8 维里没有一维有自己的值——一张 0 段谱与一张 Stellium 谱的主导维读数是同一条 `SR_base` 曲线，维度之间的比较也只是「谁占的份额大」。#44 要的是**绝对技法星级**：一个维度该说「这张谱的速」「有多难」，单位与 canonical 段位阶梯同一把尺。

## 决策内容

1. **8 个技法分值改为逐技法绝对锚定律：`SR_k = a_k · r_k ^ exp_k`，每个技法一套 `a/exp`。**
   锚定律的家族取自应变侧同一条（`SR = a·S^exp + b`），**截距 `b` 固定为 0**：驱动的零就是该维的零（`radar.compute_raw_technique_drivers` 在纯米谱上把 LN 四维精确清零，`tests/test_radar.py` 钉着这条），而带截距的拟合等价于「没有这一技法的谱也有 `b` 颗星」，会把雷达的零底整个抬起来。保留零底后 `a` 与 `b` 本来也不可分别辨识（`a·(r/b_ref)^exp` 是同一族），剩下的参数就是增益与指数。
   *实测代价*：自由截距能多买 1–2 张落带/轴（jack 11、tech 10、speed 12、stream 14、ln_general 13、ln_tech 13、ln_inverse 10、ln_release 14），代价是每条轴的零读数变成 `b`（2.6–3.7★）。

2. **总星级取 (α)：8 个绝对技法星级的最大值**（`synthesize_star_rating`），`p_norm` 与 `damping_coeff` 两个字段随之删除。
   工单给的次序是 (β) p-norm 优先、(α) 兜底，并明写「不要在 (β) 上反复调参硬凑」。**实测 (β) 不达标**，两次测量都指向同一结论：
   - 用逐轴最优锚表（本 ADR 记录 3 的「本工具」列）：四档锚点中位 **0th 4.514（带 [3.0, 4.0]）、5th 6.045（[5.0, 6.0]）、10th 8.359（[7.0, 8.2]）、Stellium 10.718（✓）**，**三档出带**；
   - 用本 ADR 选定的锚表：(β) 下四档中位 3.828 / 5.796 / **8.796（[7.0, 8.2] 出带）** / 11.059，且**总星级只有 43/120 落带（(α) 下是 77/120）**。
   damping 项原本就是「多面手加成」：在份额语义下它是相对形状的一部分，在绝对星级上它只是给每个谱白送 0.3–1.0★（`power_sum ∈ [1,8]` → 因子 1.0–1.28）。故按工单退 (α)，并把两个旋钮一起删掉（它们不再被任何算子读）。
   **实现口径的一处精确化**：工单写「总星级 = 主导维分值」，实现是 **8 个分值的最大值**（`max(radar.to_vector())`，即 p-norm 的退化端）。两者在 **54/120** 张谱上不同（本数原记 59/120；2026-09-23 在 HEAD 上复核为 54，原始值与 4 位舍入两种读法都是 54）——驱动的 argmax 轴不一定是分值最高的那轴（见开放问题 2），而那些谱的 `synergy_bonus`（`SR_norm - dominant_score`）就是这个差。字段名沿用旧名，但它已经**不是**「协同增益」而是「最高分与主导维之差」，改名会动元数据契约（下游逐圈抄写），留作 #46 一类的工作。

   `aggregate_p_norm` 本身保留：profiler 的**玩家侧**总星级仍用它（`PLAYER_AGGREGATION_P_NORM` / `PLAYER_AGGREGATION_DAMPING`，家在 `profiler/aggregate.py`），只是 `p` 与 `damping` 改为必填参数、不再是引擎选项字段——它们不移动任何谱面的星级，不该进引擎指纹。

3. **`dominant_technique` 仍是原始驱动的 argmax**，`dominant_score` 是该维的绝对技法星级。
   这一维的语义是「这张谱是拿什么铺的」（驱动在算子自己的单位下比大小），下游按它判技法是守恒的（`downscaler.validator` 的主导维不变门禁、本维命中率、诊断断言），#50 不改它。**代价（未解）**：绝对星级下分值的 argmax 与驱动的 argmax 不必一致，见「开放问题 2」。

4. **技术锚表是标定常数**：家在 `calibration.StrainStarCalibration.technique_anchors`（8 条 `TechniqueStarAnchor`），`RatingOptions.technique_anchors` 有同名字段，随引擎指纹移动版本。

## 开放问题（未定，不得实施）

1. **±8% 落带在参数化标定族内不可达**（本 ADR 记录 3 的表）。票主裁定「接受边界 / 加宽标定族」，**加宽一条已按三种形状实测**，结果如下（票主据此可再定）：
   - **锚点插值**（在 0th/5th/10th/Stellium 四个 tiers 的实测驱动上做 log-log 插值）：**更差**，8–14/15；且梯形外推会爆（ln_general 的 10th↔Stellium 两结点靠得太近，Stellium 以上外推到 47★、Zenth 47.42 对 9.7）。
   - **单调结点曲线**（结点星值自由、单调约束）：能逼近上界 15/15，但结点间距一大一小就让区间外斜率失控（实测出现 `math range error` 级的外推），**即「把 15 个点拟合了事」的具体代价**——而外推区间正是玩家铺面所在。
   - **两段幂律（一个膝点，4 参数，两侧都是幂律因此外推行为正常）**：jack 10 / tech 10 / speed 11 / stream 13 / ln_general 13 / ln_tech 12 / ln_inverse 10 / ln_release 14 —— **仍只有 3/8 达标**。
   结论：**±8%/≥13 这条线在「不是把阶梯制表」的前提下达不到**，因此按 (a) 接受边界并写进 CI；要真正达标只剩 (c) 动驱动层——**这条路由 #53 承接（2026-09-23，#44 收尾裁定）**。**票主对 (c) 的两条补充更正（2026-09-23）**：
   - **jack 的 0th/1st 倒挂不是驱动缺陷**：该倒挂曾解决过，残差来自 1st 谱主体是「切中带叠」——属 Jinjin 段**选铺**问题，不该在驱动层追。
   - LN Inverse 8th 的「release 读数高于 inverse」**与体感一致**（票主实测），故它是正确读数、不是缺陷（见开放问题 2）。

2. **跨维可比性（绝对星级的固有代价，已裁定）**：每轴独立标定后，同一条分值序列在不同轴上不再保序——实测**本维主导 80/120**（驱动侧 89/120）。票主对唯一那条翻红的期望给了体感判据：
   - `LN Inverse 8th`：`ln_inverse` 5.56 ≤ `ln_release` 6.03（驱动侧 inverse > release 仍成立）——**票主实测该谱体感 release 确实比 inverse 难**，故这是**正确的读数**，是断言过期而不是标定错。
   处置：`tests/test_ln_alignment_diagnosis.py` 的该断言改成**双向记录**（`RELEASE_LEADS = {"8th", "10th"}`：记入的 tier 反过来断言 release 领先，其余 tier 仍断言 inverse 领先），「本维主导」仍按驱动判、不变。
   **实测到的翻转比一条谱宽**：LN Inverse 阶梯上 8th/9th/10th/Gamma/Azimuth 五级都是 release 更高；LN General 阶梯自己也在中段来回翻（15 级里 6 级 release 更高，而 general 领先的那些里最薄的余量只有 0.05★（5th）与 0.09★（Stellium））。这与 ADR-0015「两条 LN 阶梯在锁深上互相交错、release 是 general 基座的修饰项」一致——即 LN 两轴的**相对刻度本身就是交错的**。是否要把它们钉成一致的相对序（会牺牲逐维落带），是开放问题 2 的另一半，未定。
   **票主 2026-09-23 裁定：LN 两轴保持现状**（允许翻转，不钉一致相对序）。即「同一条分值序列在不同轴上不保序」是本设计**接受的语义**——8 个轴测的是 8 件不同的事，交错是信息；代价是分值的 argmax 与驱动的 argmax 只在 **66/120** 上一致（原记 80/120，2026-09-23 更正——80/120 是**分值 argmax = 本轴**那个量，见「收尾复核」），读雷达时必须连 `dominant_technique`（驱动判）一起读。禁止翻转那条路（把「本维主导」提到落带之前）因此**不做**，留作记录而非待办。
   另 2 条（`Regular Tech Stellium`、`Regular Stream Stellium` 被判给 speed）是 #52 已量化的 Ω_irreg 分辨力问题，与本票无关。
   *（记录：选定表把另外两条 `LN General 5th` 与 `Regular Jack 1st` 自愈了——因为选择目标里含「本维主导」这一项；单看逐轴最优拟合时它们会翻红。）*

3. ~~**全库验收线被本次切换压低**~~ **已裁定并落地（票主：「可以放宽」）**：Phase 2 的 `mean ρ ≥ 0.98 / mean τ ≥ 0.94 / 倒挂 ≤ 20` 实测为 **mean ρ 0.9816 ✓ / mean τ 0.9255 / 倒挂 22**，故 `mean τ` 与倒挂上限重基线为 **0.92 / 24**（余量口径同逐技法闸门），`mean ρ` 不动。原因是星阶梯的序现在来自**逐轴驱动**（τ 0.79–0.96），切换前主要来自**应变阶梯**（密度序，ρ 0.968–0.989）；`guard` 里记着旧值（0.94 / 20，实测 0.940 / 16）。
   **2026-09-23 订正（实测，非转述）**：`0.940 / 16` **不是被本切换换掉的那版引擎**，而是 **pre-#47**（`96a236f`，实测 mean ρ 0.9830 / mean τ 0.9405 / 倒挂 16，与该注释所记一致）。本切换实际替换的是 **`0385e7a`**（PR #54 的合并基点），实测 **mean ρ 0.9706 / mean τ 0.9167 / 倒挂 17**。即：跌到 τ ≈ 0.914 发生在 **#47 的 K_base 修订**，本切换把 τ / ρ **抬回** 0.9255 / 0.9816，只多了 5 处相邻倒挂。**且切换前的 main 两道闸门本就是红的**——`batch --guard` 报 Regular Speed τ 0.809、LN Inverse τ 0.867（红线 0.88），`tests/test_120_benchmark_guard.py` 3 failed / 5 passed（含 mean ρ 0.9706 < 0.98）。因此 `guard.py` 里那句「旧值」的措辞同期改为「pre-#47 的读数」并补上这三组数；本条不再作为「切换的代价」引用。

5. **两处下游已按票主裁定落地**（原为「再作更改」，做法如下）：
   - **降阶器改用「星级对星级」（做法 A，票主选定）**：`WindowedPeakBatchPruner.prune` 新增 `target_sr` / `rating_options` / `radar_options`，给了目标星级时**收敛判据换成引擎自己的星级**（每轮用 `compute_technique_radar` + `synthesize_star_rating` 重评候选，复用该轮已算出的 P90 应变，不重复算应变）；应变阈值降级为**窗口选择器**（`TwoTierDanMapper` 仍按应变锚定律从目标星级推出它，作为「多高的峰算太高」的单调代理）。显式给了 `--target-strain` 的调用保持旧判据（要应变就是要应变）。`PruningResult` 因此多出 `target_sr` / `initial_star` / `final_star`，`pipeline` 在未指定 `target_strain` 时传入目标星级。`mapper.star_rating_to_strain` 本身保留，位置与语义都变了。
   - **`strain.compute_8d_strain_timeseries` 保留机制、改掉说法（本 ADR 作者决定）**：它把维度分（绝对技法星级）经**应变锚定律**换成应变当曲线电平——读的是「这条维度在应变尺上要多高」。**机制保留的理由**：profiler 用同一条定律把玩家的能力应变再换回星级（`profiler.response`），**往返单调**，所以「玩家的能力是否超过这张谱在该轴上的要求」在哪个空间判都一样；换掉它等于重做 profiler 的按维分解，超出本票范围。**改掉的是说法**：`strain.py` 里写清了这是电平、不是「两条定律是同一个函数」，并记下曲线形状是原始权重块（重述 jack/burst/flow 常数而非读 `RadarOptions`）——即 **issue #49** 仍未闭合的那条。

## 收尾复核（2026-09-23，工单 #44）

#44 是这条链的终点（#52 → #50 → #44），而它的引擎实作就是本 ADR，已由 #50 落地。本轮**不改引擎**，只逐条实测复核：引擎版本 `v1a331dc6`、星级指纹 `sha256:81e4de64…`（与实施记录 2 一致）、`pytest` 2 failed / 632 passed（两条均为 Ω_irreg）、`batch --guard` PASSED（四档锚点 3.508 / 5.450 / 7.850 / 10.180）——**四条决策的结论都按实测成立**。

**两处数字错误（同一类：三个 argmax 量被互相混淆）。** 三个量实测如下，各自的读法一并写死，免得再混：

| 量 | 实测 |
| :--- | ---: |
| 分值 argmax == 该谱**本轴** | 80/120 |
| 分值 argmax == **驱动** argmax | **66/120** |
| **驱动** argmax == 该谱**本轴** | 89/120 |

`dominant_score` 就是 `scores[驱动 argmax]`，所以「分值 argmax == 驱动 argmax」与「`dominant_score == max(8 个分值)`」是同一句话——**66 与 54 是同一个测量的两侧**（一致 66 / 不同 54；原始值与 4 位舍入同值）。据此更正两处：决策 2 原记「59/120（不同）」→ 54，开放问题 2 原记「80/120（一致）」→ 66——**后者是把「本轴」那个量抄成了「驱动」那个量**。

**一行过期记载。** 实施记录 4 原记 5 条 `*_alignment_diagnosis`「**未改任何断言**（…剩一条待裁定）」，与开放问题 2 的实际处置矛盾：该断言已改为双向记录（`RELEASE_LEADS`，提交 `36b6170`），红灯是 **2 条**不是 1 条。

**移交 #53。** 本 ADR 未达成的验收线——逐维/总星级落带（开放问题 1）与 `tech`/`ln_inverse` 的红线（开放问题 4）——连同那 2 条红测试一并由 **#53** 承接；#49（开放问题 5）仍归 #49。两处更正与这一行都记在此处，免得下一个读者再拿旧数当准绳。

## 票主裁定（2026-09-23，横向对比之后）

本轮把本 ADR 的切换与**它实际替换掉的那版引擎**（`0385e7a`，PR #54 的合并基点）在同一批冻结 120 谱上逐项对量，量法：两棵源码树各自跑 `evaluate_intrinsic_difficulty`，阶梯指标用 `monotonicity.evaluate_tier_sequence`，落带口径用 `guard.TECHNIQUE_BAND`，星值取 `star_rating`。四条裁定：

1. **不回退。** 相对被替换的引擎：canonical 总星级落带 **40 → 77 / 120**、逐轴落带 **55 → 76**、平均绝对误差 **0.864 → 0.561★**、mean τ **0.9167 → 0.9255**、mean ρ **0.9706 → 0.9816**。旧版的「稳」有一半是假的——`rho(star, sr_base)` 实测 **0.988**，即它的总星级基本就是应变序（密度序），因而把驱动层的全部缺陷盖住了。回退还要连带重置降阶器的星级收敛判据（决策 5）。

2. **官方 sr 按产品判断。** 决策 2 把官方 sr 降为诊断指标；票主裁定**它仍是玩家感知难度的标尺**，因此切换后 `star` 对官方 sr 的 **MAE 0.638★ → 0.840★、ρ 0.9704 → 0.9309** 要当作产品代价对待，不能只当统计口径。该指标（引擎 `star` vs 官方 sr 的 MAE）应进 `--guard-metric` 的诊断集。

3. **顶部形态移交 #53（已补进该票验收）。** 新增验收：「各技法梯队顶部四级（`10th → Gamma → Azimuth → Zenith → Stellium`）的驱动形态必须单调」。实测 **8 条梯队里 5 条不达标**（Regular Jack / Regular Tech / Regular Stream / LN General / LN Tech；Regular Speed / LN Inverse / LN Release 单调）。且**星级的倒挂与本维驱动的倒挂同源**（Jack 4/4、Tech 3/3、Stream 3/3、LN General 2/2、LN Release 1/1 完全重合）——**本 ADR 的映射无责**：逐轴锚定律是单调映射，改不动本维次序（实测 Regular Stream 驱动 τ 0.924 = 星级 τ 0.924）。

4. **跨维可比性单开一票（必须解决，代价可承担）。** 8 条锚定律独立拟合（指数 0.093–0.879 相差近十倍）使「同一段位」在不同技法上的读数不等价：Stellium 上 Regular Stream **9.76★** 对 Regular Speed **11.55★**（canonical 同为 10.50）。实测把目标函数从「逐轴最大落带数」换成「对 canonical 的对数最小二乘」，可把**同段位跨轴极差从 2.78★（最差 7.72★）压到 1.59★（最差 2.61★）**、消除 12.0★ 触顶（4 → 0）、把分值 argmax = 驱动 argmax 从 66 提到 **89/120**；但单目标下 mean τ 掉到 **0.8905**（低于现行 0.92 线）、倒挂 22 → 28。故实施形态必须是**多目标重搜**（对齐项 + 阶梯线硬约束）。票主要求同时**评估复活 (β) p-norm**（决策 2 当初按实测退 (α) 的两个旋钮，在轴对齐后是否重新可用）。**前置依赖：裁定 3 的顶部形态**——驱动自身在顶部倒挂时，任何映射都无法让那两级跨轴对齐。
