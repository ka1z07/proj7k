# 0027. 从音频生成 7K 谱面

- **状态**：accepted（2026-10-10；Kai 选定「从音频出谱」路线，设计说明见项目里的「从音频出谱：7K 谱面生成器设计说明」）。
- **背景**：工具链能评难度（引擎）、能把已有谱降阶（ADR-0021/0025），但不能从一首歌出一张新谱。玩家想要的是：任意一首歌，指定段位或星级，得到一张节奏跟着音乐、能打、难度准的 7K 谱。

## 决策内容

1. **新包 `proj7k.generator`，第一版只出米键。** 流水线：解码 → 起音强度 → 节拍网格 → 选点 → 配键 → 引擎打分，星级不达标就调强度重来。长条要判断「音持续多久」，放到后面。
2. **解码不引入重依赖。** `.wav` 用标准库读；mp3/ogg/flac 用 `miniaudio`（单个 wheel，没有系统库，Windows 与 Python 3.14 都有现成包）；都不行时用 PATH 上的 `ffmpeg`。不用 librosa（依赖 numba，在 Python 3.14 上装不上的风险太大）。分析只用 numpy/scipy，统一 24 kHz、10 ms 一帧。
3. **起音**（`onset.py`）：对数幅度谱的正向增量（上一帧做 3 格频率最大值滤波，抑制颤音），分低（< 200 Hz）、中、高（≥ 3 kHz）三段各自归一，再合成总强度；另记新增能量所在的频率位置（亮度）与每帧响度。整首歌只归一一次，所以副歌比前奏密。峰值相对真实起音的偏差在合成鼓上实测为 −9 ms，已扣除。
4. **Timing 三个来源，优先级从高到低**：参考谱面的全部非继承 timing point（`--timing-from`，可变速）→ 手动 `--bpm/--offset` → 自动测速。自动测速只给恒定 BPM：自相关加倍数梳子、以 170 BPM 为中心的先验选周期，±2.5 % 内按包络在拍频及其 2、4 次谐波上的傅里叶分量强度精选 BPM，±0.3 % 内若有整数或半整数 BPM 的强度不低于最佳的 95 % 就取它（歌多按整数 BPM 制作，差百分之几 BPM 在歌两端就累积成 1/4 拍）（不用相位直方图：周期恰为整数帧时直方图只落几个格子，会假装很尖），拍点取折叠最尖处，若半拍外的中频（军鼓、人声、和弦）起音更多则改取半拍外（最强脉冲有时是反拍的镲或反拍贝斯），低频最强的那一拍当强拍；把歌分四段各自定相位，相差超过 25 ms 就提示可能变速。
5. **所有 timing 都先量偏移；自动测得的 offset 提前 28 ms。** 谱面的 timing 是谱师对着 osu! 的播放听出来的，起音包络读的是解码后的文件，两者可能差几十毫秒（解码延迟、软起音）。在 ±60 ms 内找让拍点上起音最多的偏移，网格读强度时按它挪窗口，音符时间仍以 timing 为准；偏移量写进结果（`onset_shift_ms`），评测按音频格式汇总。在 Kai 曲库 40 张谱上实测这个偏移中位 28.5 ms（mp3 29、ogg 28，与解码器无关）：谱面的拍点对着起音刚能听到的时刻，包络峰在上升最陡处。所以自动测速写出的 offset 比包络读到的拍点早 `CHART_SYNC_MS` = 28 ms，生成的谱与 ranked 谱同样对齐；自动测得的 timing 也同样量偏移来读强度。
6. **网格**（`grid.py`）：每拍按音乐实际用的细分选二分（1/2、1/4）或三分（1/3），逐拍决定；每个点取附近（八分之一拍、至多 25 ms）最强起音的强度、三段强度与亮度，响度低于 −38 dB 的点算静音、不放音符。
7. **一个旋钮「强度」x 管密度与押数**（`generate.py`）。网格点的强度加上拍位加成（强拍 0.30、拍 0.18、半拍 0.06）达到 `1 − x` 才放音符；押数按权重排名分配，使平均每行 `1 + min(1.8, 0.6x)` 个音符。x 超过 1.6 后弱起音门槛逐步放开，忙的目标可以把一段的空网格点补成连续的 stream。星级随 x 单调上升，二分 x 直到落进目标 ±0.10★；落不进时报告最高能到多少星，或最接近的星级。
8. **配键**（`columns.py`）：逐行在所有列组合（7K 至多 35 种）里取代价最低的。代价含：同列间隔的平方反比（75 ms 约 6，300 ms 约 0.4）、两手近期负荷（0.5 s 衰减，拇指列各算半）、亮度在全曲中的排名决定的偏好位置（低音偏左、高音偏右）、三押以上全在一只手、与上一行完全相同，以及一个按种子的小随机项。引擎星级读的是持续负荷，对单列过载几乎看不见（见降阶器的爆发问题），所以「别让一列连打」由配键自己保证，不靠星级闭环。
9. **输出与降阶器一致**：`.osu`（版本名 `Gen <目标> (<星级>)`，Tags 带 `proj7k gen-1 seed<n>`）和带音频、背景的 `.osz`；有参考谱面时沿用它的 General、Metadata（`BeatmapID` 置 0）与背景。命令行 `python3 -m proj7k.generator`，控制台「谱面生成」页（`generate` 任务），默认用游戏当前谱面的歌并借用其 timing。
10. **评测**（`python3 -m proj7k.generator.evaluate`）：对带音频的人写 7K 谱，用它的 timing、在它的引擎星级上生成，比较行时刻（±20 ms）的精确率与召回率和星级误差；再单独自动测速，与谱面主 BPM 比（准确 / 差一个八度 / 错）以及相位误差。来源是 osu!stable 的 Songs 文件夹、解压的 .osz，或 osu!lazer 曲库（只读）。

## 后果

- 合成鼓（已知每个起音）上：120–225 BPM 的 BPM 与相位都测准；230 BPM 以上测成一半，115 BPM 以下测成两倍。生成谱在 1.5–7.9★ 都能落进 ±0.1★，低目标时 95 % 以上的行在真实起音 20 ms 以内。在 Kai 的 osu!lazer 曲库上第一轮评测（40 首，每首一个难度）：星级误差中位 0.055★；行时刻精确率中位 0.59、召回率中位 0.69；自动测速 58 % 准确、18 % 差一个八度；准确的那些相位普遍比谱面晚约 28 ms。据此改了精选 BPM（原先的相位直方图偏爱整数帧周期，造成 142.86 这类 1–2 % 的误差）、加了反拍纠正与第 5 条的偏移测量。高段长条谱星级偏低是因为第一版不出长条。第二轮（同样 40 首）：精确率中位 0.67、召回率中位 0.85、测速准确 73 %、星级误差中位 0.054★；BPM 准确的 29 张里 23 张相位都在 +14…+42 ms（即上面的 28 ms），另 6 张锁在反拍上，评测为此加了各频段在拍上与半拍外的起音比（`onbeat_ratio`），用来决定该看哪个频段判拍。第三轮（加了 28 ms 后）：BPM 准确的 29 张里 19 张相位在 ±10 ms 内、22 张在 ±15 ms 内；锁在反拍的 4 张低频都是反拍更强（拍上 / 半拍外 0.60–0.84），中频则 40 张里 39 张拍上更强（低频 31 张、总强度 35 张），所以判拍改看中频。另有 3 张差 1/4–1/3 拍，都是 BPM 估得略偏（143.71 对 144 等），由取整修正。第四轮：相位 ±10 ms 内 22/29，反拍的 4 张全部修好，新坏 1 张（Fusyoku ressentiment，40 张里唯一中频反拍更强的）。
- 参数都是常数，改它们不动引擎，不影响星级指纹与护栏。
- 后续：长条（持续音）；用谱面库下载的 .osz（音频 + 人写谱）学选点、押数与谱师风格（设计说明第 3 阶段）。
