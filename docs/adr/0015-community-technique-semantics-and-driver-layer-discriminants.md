## 实施记录（工单 #52 阶段①，2026-09-22）

落定的形态与标定值，以及测量推翻或改写的东西。**本段记录已发生的权衡，不是排期表。**

**1. ln_inverse 重构为「全锁程度 + 反相密度」（决策 6 落地）**

新增特征 `features.inverse_press_share` / `inverse_press_rate` / `inverse_gap_median`：同轨「尾点 → 该轨下一次按下」的间隔，以**动作时钟窗**（`gap / delta_t_action`）为单位 —— 换谱即换刻度，所以"立即松手、立即按下"在快谱上按同一物理间距读得更紧（CONTEXT.md 反键 BPM 缩放律），不需要额外的 BPM 乘子。`FeatureOptions.inverse_press_window_steps = 1.0` 是"立即"的定义（一个记谱格）。

三个候选量的分工**分别测量**后才发现（120 谱）：

| 量 | 本维阶梯 τ/ρ | vs 另三条 LN 梯队 AUC |
| :--- | ---: | ---: |
| `inverse_score` | 0.905 / 0.975 | **0.526（抛硬币）** |
| `lock_load`（全锁程度） | 0.505 / 0.664 | 0.887 |
| `inverse_press_rate` | 0.924 / 0.982 | 0.719 |
| `inverse_press_share` | **0.086 / 0.107** | **0.997** |
| `median_gap` | 0.571 / 0.767 | 0.011（方向相反：越小越反相） |

即：**share 是纯形状量**（辨识近完美、排序零能力），**rate / score 是纯水平量**（排序好、辨识差）。因此 share 只做**饱和门**（`ln_inv_share_gate = 0.75`），不做权重：把形状量乘进载体，梯队的非单调性会一起乘进去（实测 `share × (lock + rate)` 只排到 ρ 0.686，低于默认闸门）。门值按语料标定：非反相的 LN 谱无一达到 0.75（LN General 峰值 0.582、LN Tech 0.60、LN Release 0.461）。

`inverse_score` **保留在轴内**（决策 6 把它钉在"验证后再定去留"，而软上限落地后它不再劫持）：轴的本维阶梯由 0.733/0.854 升到 **0.790/0.900**。

**2. 决策 4 的形态落地；等长退化的定义在实施中修正（票主裁定"按需要改定义"）**

`g = 1 + k·lockd` 与 `ln_release_lock_gain = 1.0` 已落地；`ln_release_gain`（既有字段）承担**交叉点**：`gain × (1 + k·lockd)` 在 `lockd = (1/gain − 1)/k` 处穿过 General 基座，标定为 **0.55**（gain = 0.645），高于 LN General 阶梯最深锁（0.54）——**这是必须的**，否则 General 轴在自家梯队的深锁段全被 release 拿走。代价：LN Release 本维命中 8/15 → **7/15**。

*实施中改掉的量的定义*：`release_lock_depth` 原先数"抬手瞬间同手仍有几个键在按"，实测发现**错开起点的等长谱读 2.11**（包含判据只要求"某轨在我之后按下且尚未结束"，等长+错开满足它），于是 AC7 点名的第二种合成谱（chordstream 米键全换等长 LN）**不退化**。按票主裁定改为：**只计长度不同的共持键**（长度按毫秒取整比较，即 osu! 记谱的粒度）——同手同长的键不构成"保持/松开"的判断，谱面自身的结构已经回答了它。这正是 ADR 依据一说的"长度参差下的松放判断"，也把两种等长合成谱都精确退化为 0。改后四梯队中位次序不变（Inverse 0.860 > Release 0.515 > General 0.318 > Tech 0.189）。

*验收线调整（票主授权）*：`LN_RELEASE_MIN_HITS` 8 → **7**。理由不是放宽而是纠正判据：Release 轴是 General 基座上的修饰项，交叉点必须高于 General 阶梯最深锁，而两条 LN 阶梯在锁深上互相交错——Release 阶梯的低段锁得不比 General 中段深。AC1 已明写本维"不要求本维主导自己的阶梯（容许 ln_general 主导）"，故"本维命中数"对该轴本就是错判据。工具里记着这次改动与理由。

*第二项代价（同一条形态的）*：`release = gain·(1 + k·lockd)·gen` 使 release 在**每张长条谱**上都落在 general 的 0.63–1.0 倍之间，于是这些谱的次高/最高比天然贴近 0.8–1.0 —— LN General 组的分离中位 0.712 → **0.876**、LN Release 0.655 → **0.874**（LN Inverse 反向大幅改善：0.736 → **0.301**，本维命中 1/15 → 12/15）。**三项要求在这条形态下无法同时成立**：交叉点 > 0.54（General 保住自家梯队）× Release 命中 ≥ 8（需交叉点 ≤ 0.51）× 分离 ≤ 0.5（需 gain ≤ ~0.3，即交叉点 ≥ 3）。全库分离中位 0.698 → **0.8076**、>0.8 张数 44 → **61**，**票主裁定接受**为阶段② 起点（CI 以棘轮断言守住不得再恶化，提交阈值仍留在工具里作靶）。

*推翻*：`release_lock_depth` 的退化点只在**同起同长**（所有长条同起同止，抬手时全手同时松）时读 0。**错开起点的等长谱读 2.11**：包含判据要求"某轨在另一轨开始后被按下且尚未结束"，等长+错开满足该条件。AC7 点名的第二种合成谱（chordstream 米键全换等长 LN）因此在现定义下**不退化**，`tests/test_ln_release_degeneracy.py` 把它写成 strict xfail 并记录实测值。要闭合需要改量的定义（只计"比我更长的长条"）或换量——**未决**。

## 实施记录（工单 #52 阶段②，2026-09-23）

**0. 动工前的实测推翻了阶段② 的立项措辞。** 工单写「speed / jack / stream 在 BPM 不变甚至反降时排不出序，缺的是**谱形分辨力**」。实测两处都不成立：

- **跨技法判别力早已不缺**：Regular Speed vs Regular Stream 上 `burst/nps` AUC 0.991、`avg_nps/notation_bpm` AUC 0.996；Jack vs Stream `jack_ratio` AUC 0.947；Speed vs Jack `notation_bpm` 与 `burst/nps` 双双 AUC **1.000**。
- **三条米侧阶梯的真值本身就是密度序**：`peak_4m_nps` 单独就有 speed ρ 0.975、jack 0.982、stream 0.989（stream 单独就已达 AC1 靶心）。八条阶梯**无一例外**被它排序（ρ 0.968–0.989）——**段位阶梯就是密度阶梯**。
- LN 侧之所以一直能排序（0.905/0.971、0.886/0.961），是因为 `ln_gen_flux` 乘了 `avg_nps`；米侧没有任何等价项。

即：**缺的不是分辨力，是载体**——而载体正是 ADR-0008 修订 1（把 density 从 `K_base` 拿掉）与分离 AC 要拦的东西。这个矛盾是阶段② 的全部内容。

**1. 四条米侧轴拿到 peak-density 载体；参考值由一条可检验的规则定，不拟合**

形态：`r_x *= peak_4m_nps / rice_density_reference`，挂在**规则之后、返回之前**（与 `r_ln_rel` 同一先例）。理由是可测量的：规则比的是各轴的技法负荷，若载体先于规则施加，Rule C / Rule D 的触发条件会随之改变，等于顺手重标定了它们。

`rice_density_reference = 40.7` 的规则是：**载体在任何 LN 谱上都不抬高米侧轴**。`peak_4m_nps` 把长条头按米音符计数（决策 3 保留这条计数口径），因此长条为主的谱可以比米谱更密；参考值低于这个上限，就会在恰恰不该赢的那些谱上抬高米侧轴。全库最密的 LN 谱是 `LN General Stellium`（40.69），也正是约束所在：参考值降到 30 左右它的米侧读数就反超 `ln_general`，取 40.69 时它的余量恰好回到载体前。实测指标在 40–70 全平，30 以下才破。

**四条轴而非三条。** 只给三条加载体不是更小的改动，而是另一个改动：第四条就成了唯一不在阶梯密度刻度上的米侧轴，并会在别处悄悄夺走主导。实测于 `Regular Jack 1st`（该谱的定义特征是 41 个双键叠键）——漏掉 `tech` 让它拿到 argmax，jack 掉到 1.91★，低于 `tests/test_stream_vs_jack_diagnosis.py` 的 3.0★ 下限。四条同乘一个因子时，载体在米侧组**内部**是公因子，米侧之间原有标定被完整保留，动的只有米侧与 LN 侧之间。

**2. 被否证的候选（勿再提）**

- **社区词条点名的分量不排序本维阶梯**：`burst×(1+tortuosity)` ρ 0.886、`burst×low_chord` ρ 0.871，都低于该阶梯自身的密度序 0.975。折返 / 单轨密度 / 低叠键做的是**跨技法区分**（驱动已在做，AUC 0.99），不是阶梯内排序。工单待证项「speed 重构后读折返、单轨密度、低叠键」由此结案：**这三个都不该进算式**。
- **技法专属峰值密度**（各轴读自家音符集的 4 小节峰值）：`peak_single` 在四条 Regular 轴上只有 ρ 0.22–0.53；三种口径的侵入地板 29–34/56，都不优于全局 peak4m 的 31/56。
- **指数比**：`peak4m^a × shape^b` 只有 a:b = 1:1 可行（a 再小三条阶梯就过不了红线）。因为乘积的序在两个指数同比例缩放时不变，b 固定为 1 即「保留既有形状项原样」。

**3. AC2 与 AC3 同为结构性不可达——#50 的判据需要据此重开**

- **AC2（侵入 → 0）**：现状 **15 → 13**。13 条里 6 条属于**自己阶梯都过不了闸门**的轴（tech 4 条、ln_inverse 2 条），按工单自己的「分层读」纪律记入已知边界；剩 7 条全部 ≤ 0.021。（工单写的 17 是阶段① 之前的数，对应 `@old_tree` 基线；阶段① 已消 2 条：`ln_release on LN Inverse` 与 `ln_inverse on LN Tech`。本轮独立复算与仓库里的 `driver_ladder_baseline.json` 逐对相同。）**不可达的方向性证明**：八条阶梯全由 peak4m 排序，所以任何读密度的驱动都会把任意阶梯排到 ~ρ(peak4m on L)。若 8 个驱动都取纯 peak4m，侵入是 **31/56**——比现状差一倍。**读密度（AC1 要求）与不侵入（AC2 要求）方向相反**，现状的 13 条正是形状项一路压着的结果。
- **δ 不可拟合**：56 对余量在 0 附近**连续**（相邻秩的间隔最小 0.0000 / 0.0028 / 0.0034），没有天然 δ。用一个恰好大于 0.021 的 δ 把 7 条判为通过，是纯拟合。
- **AC3（分离 ≤ 0.5）**：见 `tests/test_radar_orthogonality.py` 的证明——`ln_release = gain·(1+k·lockd)·ln_general` 使比值恒 ≥ 0.645，全库 60 张 LN 谱的 `min|release/general|` = 0.621，其中 30 张的最高两次高正是这一对，即 25% 的语料被钉在 ≥ 0.62。要中位 ≤ 0.5，剩下 90 张里需 61 张 ≤ 0.5（现状 32/120）。

## 决策内容（草案）

1. **技法语义以社区定义为准；雷达 8 维的维数与名字不变。** 新增 `CONTEXT.md` 技法词条（高速单轨流 / 全锁反相长条 / 长条尾盘抓握），改的是每一维驱动**读什么量**，不是维数。理由：8 维是雷达画像、降阶器技法守恒门禁（`downscaler/validator.py:119-120` 的方向余弦 + 主导维不变）与仪表盘多边形共同依赖的契约。
   *权衡*：拒绝「把 speed 拆成密度维与谱形维」——维数是会被下游逐一圈抄写的形状，拆维的代价全部落在 #46 的消费者审计上，而语义问题不需要靠改契约来解决。

2. **动能只能放大无序度，不得充当载体。** tech 的动能输入必须进乘性项（放大 $\Omega_{\text{irreg}}$），**不得回到 `K_base`**。依据是 ADR-0008 修订 1（`docs/adr/0008-…md:55-59`）：把 $r_{speed}$ 放回 `max` 之后，每一张 speed 谱都变成「以 speed 为特征的 tech 谱」（实测 Regular Speed 组 15 张有 6 张最高维是 tech，领先仅 7%–15%），配套代价是 `tech_saturation_gain` 从 0.15 提到 0.8。
   *权衡*：拒绝加性项与「新载体项」——两种形状都等价于把动能重新变成独立难度来源，正是修订 1 已经否定过的东西。乘性放大天然满足约束：动能再高，$\Omega_{\text{irreg}}$ 不无序就放不出 tech。

3. **米侧驱动把长条头按米音符计数是刻意的，不加对称门禁。** `flow_count = total_notes − jack_count`（`radar.py:504`）与 `_compute_speed_raw` 的相邻异列 HO 口径（`:541-572`）保持原样，stream / speed / tech 不新增长条门禁。依据：这与资深玩家在米面混铺上评价米类技法难度的实际依据一致；混合谱的正确性要求是**主导维正确**，不是把米驱动清零。
   *权衡*：拒绝「对称门禁」（纯 LN 谱上把米驱动压到 0）。一段 chordstream 写成 ln inverse 时，`ln_inverse` / `stream` / `ln_general` 三维本就都该高——压零会把「主导维是否正确」这件真问题掩盖掉，而它才是要修的东西。

4. **LN Release 保留 general 基座，换掉的是修饰项的形态；并且不要求本维主导自己的阶梯。** 结构取 $r_{\ln\_rel} = r_{\ln\_gen} \times g$——与现式同形。**量保留 `release_lock_depth` 本身，改的是形态**：现式 `lockd / 0.5` 在等长谱上读 **0 而非 1**（不满足退化），须改成锚定退化点的仿射形式 `g = 1 + k·lockd`（k 待标定；k=1 时中位 $g$ 为 Inverse 1.94 / Release 1.58 / General 1.36 / Tech 1.23）。
   *对早先判断的更正*：本文 v2/v3 曾把 `release_lock_depth` 判为「锁深、属 inverse 语义、必须整个换掉」——**实测推翻了这个判断**（见下方依据三），该量恰恰是唯一能承担本维职责的那个。
   *依据三（跨梯队正反例，2026-09-22）*：在 60 张 LN 谱（四条梯队各 15）上，`release_lock_depth` 是唯一分得开 release 特化与非特化的量——vs LN General AUC 0.702 / vs LN Tech 0.778 / vs LN Inverse 0.138，**去掉密度后升到 0.778 / 0.862 / 0.107**（说明它带的不是密度信息）；四梯队中位数次序 Inverse 0.936 > Release 0.575 > General 0.356 > Tech 0.228，与设计意图一致。点名的那一对（`LN General` 10th 与 `LN Release` 10th，两者 avg_nps 20.97 vs 19.52，是天然的去密度对照）：General 10th 的 lockd 0.397（落在 Release 梯中下游），Release 10th 0.776（高于 14/15 张 General）——**"抬手时同手还锁着几键"就是玩家口中"松与不松的协调"的可观测量**。
   *同期被否证的量*：长度比值族（p90/p10、p50/p10、p95/p5）在三对 AUC 全部只有 0.54–0.63（p ≥ 0.22），在点名那一对上 0.556 / 0.549 / 0.538；`len_cv` / `interval_cv` / `phase_std` 在该对**方向反转**（General 10th 反而比真的 Release 10th 更"像 release"）。它们虽然正交于密度、退化也干净，但只是"好的正交量"，其微弱真信号指向 Inverse。**上一轮"偏相关 0.586"的偏差来源已定位**：那个判据问的是"沿 Release 阶梯在密度之外是否变化"（由 2nd 一段独家支撑，删掉即归零），而不是"能否把 release 特化图与 general 图分开"——**在这份数据上两者不是同一件事，后者才是设计目标**。
   *依据一（思想实验）*：把一段 chordstream 的米键全部换成**等长**长条——尾判密度看似夸张，实则认知与物理难度都趋近于零，因为每一拍的答案都一样（全放）。难度来自**长度参差下的松放判断**：每一拍都要重新判断哪一轨需要保持、哪一轨需要松开。
   *依据二（难度的上限）*：**纯靠释放而不提升密度，难度是有上限的**；Jinjin Dan 对 release 的选铺应理解为「释放特化下随密度提升，考察释放**准度与稳定性**的阶梯」。实测佐证：该阶梯被密度排序（`avg_nps` 单独 τ 0.943 / ρ 0.979），现 `ln_release` 与 `ln_general` 的 Spearman 是 **+0.950**、与 `avg_nps` 是 **+0.954**——它拿到 0.989 靠的是继承 General 通量基，而不是释放语义。
   *由此定一条判据规则*：**对 ln_release 不要求阶梯由本维主要排序，容许 `ln_general` 主导**；本维的职责是在基座之上表达释放的准度与稳定性。
   *由此定的设计目标（本维的完成判据）*：**已知一张图是 release 特化时，本维要能说出它在 release 上有多难**；并且要能**解释**为什么 10 段的 LN General 谱不是 release 特化、而 10 段的 LN Release 谱是。因此修饰项 $g$ 必须同时满足三件事：① **正反例可分**——在 LN Release 梯队上的取值显著高于其它三条 LN 梯队；② **对等长精确退化为 1**；③ **由可命名的分量构成**，使"为什么不是特化"能逐项作答，而不是一个黑箱标量。
   **本文件 v1 草案把「尾点越孤立则越难」写进本维是错的**；孤立度、释放弦宽、反相时距一类**运动协调**量属 ln_inverse（见决策 6）。
   *后果*：须追记 ADR-0008 修订 2（该 ADR 的已知边界即记在此处）。

5. **判别量取「引擎里已有的单边不变量」，不靠驱动分值排序，也不新造特征。** 实测（30 张 LN 谱）：驱动分值分不开两条梯队（见背景），真正分得开的是 Rule E 那道门的条件 `mean_locked_fingers ≥ 4.0`（`RadarOptions.inv_lock_gate`——**既有引擎常数，不是拟合值**）：LN Inverse 触发 12/15、LN Release **0/15**，准确率 0.900、精确率 1.000；把阈值最优拟合到 4.264 收益为零，故判据可写成 CI 断言。**措辞必须单边**：「LN Release 永不触发 Rule E」——不得写成「LN Inverse 一定触发」（3 张低锁谱漏网，见待证）。
   *已否证的假设*：`isolated_tail_share` 不能当判别量——它在 LN Inverse 上比 LN Release **更高**（AUC 0.671，方向相反），信号是「尾点更孤立」而非「释放主导」；它区分 LN 与非 LN（AUC 0.82）反而强于区分 Release（0.72）。它仍可作分量，但**家不在本维**——尾点孤立度是运动协调量，归属 ln_inverse（见决策 6）。
   *保留的反例*：「立即松手、立即按下」的时距在全仓**不存在**（`features.py` 无任何 release→press 间隔量），若后续证明必需则新增，并按标定登记表口径给它一个家。

6. **ln_inverse 重构为读「全锁程度 + 反相密度」；`inverse_score` 暂时保留。** 依据是其判别力实测（AUC 0.582，见背景）与它在算式中的权重（3.50）严重不匹配。`inverse_score` 是否删除**不在本决策内**——它对「反相密度」本身可能仍有信号，只是对 inverse/release 的**区分**没有；阶段① 先在反相密度上验它，再定去留。

7. **LN 侧接受「严格不等号不可达」。** Jinjin Dan 阶梯下存在无法用严格不等式分开的驱动组合（四条 LN 梯队在特征空间本身重合）。跨技法判据取**余量 δ + 分层读**：只对已过闸门的技法硬性要求该判据，未达标者显式记入已知边界——与 #50 已定的「逐维落带只对单调性达标的技法硬性要求」同构，同一条纪律不在两张票里写成两套口径。
