# 0049. 运行中的任务可以取消，只停在安全点

- **状态**：accepted（2026-10-31；Kai：「增加一个取消任务的按键」）。补充 ADR-0043：以前只有排队中的任务能取消（PR #122 的任务页），运行中的任务只能等它跑完，一个 Mapperatorinator 生成要 4–16 分钟。
- **背景**：Python 的线程不能从外面杀掉；就算能，杀在写 lazer 库或 profiler 数据库的中途也会把库写坏，正是 ADR-0043 要证明不会发生的事。所以取消必须是协作式的：任务自己在「什么都没写到一半」的地方查看停止标志。

## 决策

1. **停止标志与安全点**（`proj7k.cancel`）。任务线程运行动作时监视自己的 `stop_event`（`cancel.watching`）。耗时的代码在安全点调用 `cancel.checkpoint()`：标志已设时抛出 `cancel.Cancelled`，任务状态变成「已取消」，释放资源，后面等它的任务照常开始。不在任务线程上（命令行、测试）时，`checkpoint` 什么都不做。
2. **`Cancelled` 继承 `BaseException`**（同 `asyncio.CancelledError`），所以降难「跳过一张坏谱」、导入「跳过一个坏回放」的 `except Exception` 不会把它吞掉。
3. **安全点只设在两次完整步骤之间，从不在写入中途**：

   | 任务 | 安全点 | 停下后 |
   |---|---|---|
   | `generate` | 每次 Mapperatorinator 运行之前；运行中的模型进程（含它的子进程）立即被杀（`cancel.run`） | 只丢下本次的草稿文件夹；输出文件还没写 |
   | `generator_project` 重写 | 每个候选之前；同上杀模型进程 | 工程不变（新版本只在最后一个候选之后才建） |
   | 安装 Mapperatorinator | 每个安装步骤之前（git、建 venv、装 PyTorch……步骤本身**不杀**） | `.installed` 标记最后才写，下次从头补装 |
   | `downscale` | 每张谱之前、删减循环每一轮之前、写入 lazer 之前 | 已写出的练习谱留在输出文件夹；lazer 不动 |
   | `sync_once` | 评估每张谱之前、开始备份并写库之前 | lazer 库不动（之后备份、写库一气呵成） |
   | `import_replays` | 每个回放之前（「删旧快照 + 存新快照」之间没有安全点） | 已导入的回放保留，每个回放各自一笔事务 |
   | `profile_replay` | 对齐分析之后、存库之前 | 什么都没存 |

   `sync_revert`、`lazer_control`、`sync_setup`、`profile_player`、`profile_habits` 没有安全点：它们要么很短，要么本身就是一次写入。请求取消后它们照常跑完，结果如实显示为「完成」。
4. **子进程。** `cancel.run` 代替 `subprocess.run`：每 0.5 秒查看一次标志，设了就杀掉整棵进程树（Windows `taskkill /T /F`，其他系统用独立进程组 `killpg`），再抛出 `Cancelled`。只用于输出是草稿的子进程（模型推理）；会留下半成品的子进程（pip/uv 安装）不杀。
5. **界面。** 任务页每一行、各工具页的任务卡片都有「取消」按钮（桌面端用的是同一套页面）。排队中的任务一点就取消；运行中的任务要再点一次「确定取消？」（4 秒内），之后按钮和状态显示「取消中…」，直到任务到达安全点。服务端在 `Job.to_dict` 里给出 `stopping`，并在日志写一行「正在取消」。

## 后果

- 取消一个生成任务几乎是立即的（模型进程被杀）；取消同步或降难最多等一张谱的评估或一轮删减。
- 新加的耗时代码要自己放安全点；放在写入中途就违反了本 ADR。
- 测试：`tests/test_dashboard_cancel.py`（运行中取消、无安全点时照常完成、`except Exception` 不吞、杀掉子进程及孙进程、生成器在两次运行之间停、导入在两个回放之间停）。
