# 0034. 桌面端与玩家视角的页面：主页、游玩记录、曲库、谱面与单局详情

- **状态**：accepted（2026-10-19；扩展 ADR-0024 的控制台）。
- **背景**：控制台（ADR-0024）是一组按工具划分的页签：实时雷达、同步、降阶、生成、回放与画像。玩家打开它看不到「自己」：玩了多少、打得怎么样、最近有没有进步、哪张谱打过几次。工具之间也互不相通，在画像推荐里看到一张谱，想降阶它还得回游戏里选中。Kai 要求从浏览器看板转到桌面端，加上玩家主页、数据和游玩历史，并让玩家觉得能点开的东西都能点开、都接到已有工具上。

## 决策内容

1. **桌面端是控制台的窗口，不是第二套程序。** `python3 -m proj7k.desktop`（Windows 双击 `proj7k.cmd`，或 `deploy/desktop/install-shortcut.ps1` 建的开始菜单 / 桌面快捷方式）先找 7770 端口上正在运行的控制台（`/api/config` 带 `realm_path` 才算），没有就在后台启动一个（Windows 走 `restart-services.ps1 -DashboardOnly`，与自动更新、重启按钮同一条路），然后打开窗口：优先 pywebview 原生窗口（可选依赖，装了才用），否则 Edge / Chrome 的 `--app` 窗口（独立配置目录 `~/.proj7k/desktop`，记得窗口大小，不混入日常浏览），最后退回默认浏览器。
   - 控制台不放进桌面端进程：关掉窗口不打断正在跑的任务；自动更新重启控制台时窗口只是重连（页面本来就会重连 WebSocket）。代价是关窗口后控制台仍在后台，这与 meow 上现在的常驻方式一致。
   - 没选 Electron / Tauri：要另装一套运行时和构建链，而页面、任务、后端已经都在 Python 里。
2. **玩家页面读 osu!lazer 自己的数据库，只读。** Node 桥新增 `dump-player-data`：全部 7K 谱（含谱面集 ID、封面与音频的存储哈希、时长、BPM、加入时间）与全部 7K 成绩（含没存回放的成绩、判定统计、Mod、最大连击、评级）。`proj7k.dashboard.player.PlayerLibrary` 缓存这份快照，`client.realm` 变了才重读（最多每 10 秒查一次），游戏开着也能读。不接 osu! 在线 API：全球排名、pp 这类在线数据需要 OAuth 应用，暂不做；头像从 osu! 公开头像地址取一次后缓存在本机，取不到就显示占位。
3. **星级一律是引擎的。** 同步过的谱从难度名里的注入后缀读（带版本号）；没同步过的谱在后台按「玩过的先」逐张用引擎读一次，结果按引擎版本存进 `chart_stars.json`；开了 DT/HT/自定义变速的一局按「歌被压缩后的谱」重算星级。读过回放的局再并上画像快照里的 UR、完成度、崩盘点与各技法实力（按回放存储哈希对上，旧快照按谱面 MD5 + 时间对上）。
4. **页面**：顶栏分「我的」（主页 `/home`、游玩记录 `/history`、曲库 `/library`）与工具两组，首页改为主页。谱面 `/chart?md5=` 与单局 `/play?id=` 两种详情在外壳的侧边面板里打开（可后退、Esc 关闭），不离开原来的列表。接口 `/api/me/*` 在线程里应答，第一次读库不卡实时雷达。
5. **能点的都能点开、都接到工具上。** 外壳与页面之间用 `postMessage` 互通：任何页面都能打开谱面 / 单局详情，或带参数切到另一个工具（`P7.navigate`）。谱面页能降阶（降阶页多一个「选中的谱」来源，默认低一段）、用这首歌生成新谱（借用它的 timing）、诊断最近一局、看全部记录、试听、打开线上 7K 曲库与 osu! 官网；单局页能诊断这局（`profile_replay` 新增按回放哈希指定一局）、在 osu! 里重看（把回放从存储里拷成 `.osr` 交给 osu!lazer）、下载 `.osr`、在崩盘点切练习包、降阶这张谱；画像推荐里的谱、顶栏的当前谱面都能点开谱面页。

## 后果

- 没同步过的谱第一次打开曲库时显示 osu! 自己的星级（标 *），后台换算完再刷新就是引擎星级；换算按谱逐张做，在忙的机器上不会一下占满 CPU。
- 「在 osu! 里重看」依赖 osu!lazer 关联 `.osr`：它会导入（已有则直接显示）并播放这局。
- 主页的「画像实力」「八项技法」仍然只来自导入过的回放；没导入时页面引导去导入。
