# Spec: 7K 玩家回放诊断画像器与闭环训练系统 (Phase 4.1)

## Problem Statement

作为一名 7K 玩家，在日常打图与高难考级攻坚过程中，面临着严重的复盘盲区与训练低效问题：
1. **宏观评分缺乏技法归因**：官方结算仅提供单一的 Accuracy / Score / pp 指标，玩家无法得知自己在具体哪项技法（如 Chordjack、高密反键 LN、双手交替切键）上失分，也无法辨识自己是由于体力耐力衰竭还是由于读谱知觉倒错导致断连；
2. **微观操作病理不可见**：在面对高难图段落崩塌时，玩家难以察觉隐蔽的生理偏载——例如左手无名指离散度远高于食指、持续原位连打（$\Delta k=1$）时的敲击时钟向后漂移（越打越慢）、长条释放过早的恐慌松键或粘键拖沓；
3. **能力评估静态失真**：玩家水平具有动态波动性，传统段位通关记录无法体现近期竞技状态与巅峰能力差距，缺乏时间视窗维度的客观画像；
4. **训练割裂无法闭环**：在暴毙于特定难点后，玩家要么只能机械重打整张谱面，忍受前段垃圾时间的体能消耗；要么盲目地反复刷段位考题，形成死记硬背的肌肉定势，却无法迅速获得针对该致死段落的自适应阶梯练习图。

## Solution

遵循 [ADR-0001](file:///Users/kz/proj7k/docs/adr/0001-decouple-intrinsic-difficulty-from-player-data.md)、[ADR-0003](file:///Users/kz/proj7k/docs/adr/0003-cloud-platform-with-local-analyzer.md) 与 [ADR-0012](file:///Users/kz/proj7k/docs/adr/0012-player-profiler-and-closed-loop-training.md)，构建 `proj7k.profiler` 本地分析诊断器与训练闭环：
1. **因果时序对齐与惊慌鬼键隔离**：通过因果时序判定机制（Causal Hit-Window Matcher）单向按序消费按键帧，精确区分有效打击误差、漏键（Miss）与空轨乱敲的惊慌鬼键（Panic Ghost Tap），维护微观时序诊断的纯净度；
2. **微观生物力学与读谱病理诊断**：从回放中提取各轨 UR、左右手对称性比值、原位停滞疲劳漂移斜率（Jack Stagnation Drift）、长条尾放提前/粘键分布，并准确定位引发级联断连的前驱键形（Cascade Failure Precursor）；
3. **点对点应变-误差响应模型与段位画像**：将击键误差与铺面时序应变曲线（Continuous Strain Decay）点对点耦合，定位断连与误差发散拐点，得出玩家在 8 维技法上的有效承压上限（Effective Strain Capacity），并严格映射至 15 级权威 Jinjin Dan 标尺；
4. **双时间视窗宏观画像**：结合本地 SQLite 轻量快照，提供近 30 天滚动近期状态（Recent Rolling Form）与历史巅峰画像（All-time Peak Profile），精准捕捉玩家即时手感与理论极限；
5. **双教练模式与两阶段曲库召回**：提供以攻克瓶颈为导向的短板突破模式（Bottleneck Breaker）与长板专精模式（Specialty Push），坚决规避段位考题推图，第一阶段优先从本地已安装的曲库标签中召回同段位适宜曲目，预留未来云端精准检索；
6. **三阶梯靶向降阶练习包闭环联动**：对致死段落提取前后时序缓冲切片（High-Strain Section Slice），一键联动 `proj7k.downscaler` 自动生成 Recovery（巩固）、Bridge（过渡）、Push（突破）三阶梯自适应练习包。

## User Stories

1. 作为一名 7K 玩家，我希望通过命令行传入一个 `.osr` 回放文件与对应 `.osu` 谱面，系统能在数秒内输出该局击键的综合诊断报告，以便我立刻了解当局发挥细节。
2. 作为一名 7K 玩家，我希望系统在诊断时严格遵循官方下落式判定因果律单向消费按键，以便在发生漏键时不会将后续按键错位平摊到错误音符上。
3. 作为一名 7K 玩家，我希望系统将我在读谱崩溃时胡乱按下的多余杂键单独标记为惊慌鬼键，以便这些乱按不会污染正常击键的离散度（UR）统计。
4. 作为一名 7K 玩家，我希望能够看清左手 3 轨与右手 3 轨（以及各手指）的平均打击偏移与离散度对比，以便发现自己双腕或指间力量是否存在严重偏载。
5. 作为一名 7K 玩家，我希望了解自己在高难 Chordjack 连打过程中的疲劳漂移斜率，以便量化自身肌腱耐力是在击打几秒后开始出现动作时基滞后的。
6. 作为一名 7K 玩家，我希望系统能够独立呈现长条按下的头部判定与松手的尾部判定误差分布，以便明确区分我是“提前恐慌放手”还是“粘键延迟松手”。
7. 作为一名 7K 玩家，当我在中途断连时，我希望系统能够标定出断连前 200~500ms 内的键形特征，以便识别引发我级联断连的知觉倒错根因。
8. 作为一名 7K 玩家，我希望系统将我的击键离散度与铺面的 8 维瞬时物理应变曲线点对点对齐，以便客观计算出我在各技法维度上能够承受的最大有效应变上限。
9. 作为一名 7K 玩家，我希望系统根据有效承压上限将我的 8 维技法能力严格映射至权威 Jinjin Dan 段位标尺，以便在雷达图上清晰掌握自己各项能力的对应段位等级。
10. 作为一名 7K 玩家，我希望查看自己过去 30 天内的滚动近期画像，以便了解自己最近一个月的实战竞技状态与活跃短板。
11. 作为一名 7K 玩家，我希望查看自己的历史巅峰画像，以便确认自己各项技法曾经达到的历史最高承压天花板。
12. 作为一名 7K 玩家，我希望系统自动过滤游玩时长不足 30 秒或完成度低于 50% 的重试（Retry）对局，以便宏观画像不受热身或刷开局行为的噪声干扰。
13. 作为一名 7K 玩家，当我在高难谱面中途中断暴毙（Failed）时，我希望系统依然保留我暴毙前的高应变打击数据，以便准确探测出我的极限致死应变拐点。
14. 作为一名备战段位考级的玩家，我希望选择短板突破教练模式，以便系统能优先针对阻碍我综合晋级的最弱项技法提出强化建议。
15. 作为一名专精特定玩法的玩家，我希望选择长板专精教练模式，以便系统能顺应我的偏好，为我的优势技法提供更高梯度的挑战建议。
16. 作为一名 7K 玩家，我希望训练推荐绝不推荐段位考级曲目，以便杜绝我因过度应试而产生机械背谱的肌肉定势。
17. 作为一名 7K 玩家，我希望系统优先从我本地已安装的曲库（通过 Realm 标签与难度匹配）推荐练习谱面，以便我能够即点即练而无需重新下载。
18. 作为一名 7K 玩家，当我遭遇致死段落时，我希望系统能够截取致死点前 10 秒至后 5 秒的局部高能切片，以便我只针对核心难点进行刻意练习。
19. 作为一名 7K 玩家，我希望系统通过降阶引擎自动为致死切片生成 Recovery、Bridge、Push 三阶梯练习包，以便我能从 98%+ 准度巩固逐步过渡到原谱攻坚。
20. 作为一名多账号或与朋友共用设备的用户，我希望系统根据回放文件头自动识别玩家身份，并在本地数据库中分档隔离存储，以便互不影响画像统计。
21. 作为一名本地工具链用户，我希望通过命令行传入 `--json` 获得完整诊断数据结构，以便轻松接入其他脚本或前端工具。
22. 作为一名本地工具链用户，我希望运行 `proj7k.live` 守护进程时，打完对局后自动捕获最新回放并完成诊断，以便切回 Web 仪表盘时即可在复盘标签页直接查阅。

## Implementation Decisions

### 模块责任划分

1. **回放二进制流解码与时序解析引擎 (Replay Ingestion)**：
   - 解析标准 `.osr` 文件二进制结构，解码 Mania 专有按键比特流动作帧；
   - 提取对局元数据：玩家 Username、谱面 MD5、对局时间戳、MOD 标记、各项官方计数（300g, 300, 200, 100, 50, miss）。

2. **因果时序对齐与事件判定器 (Causal Hit Matcher)**：
   - 结合铺面的 OD 判定窗口，沿时间轴单向消费打击事件；
   - 判定窗口之外或空轨触发的敲击归类为“惊慌鬼键（Panic Ghost Tap）”，独立统计频次并执行隔离；
   - 统计分离长条头按下与尾部松手事件。

3. **微观生物力学与读谱病理诊断器 (Pathology Diagnostic Analyzer)**：
   - **离散度与偏载度**：按轨道独立计算 Hit Error 的均值、方差与 Unstable Rate（UR），计算左右手平均偏移差异比值；
   - **停滞衰减**：针对同轨连续停滞（$\Delta k=1$）区间，拟合打击时基漂移线性回归斜率（Jack Stagnation Drift）；
   - **释放偏置**：统计 LN Tail 松键窗口分布，输出粘键延迟率与提前放手率；
   - **断连归因**：标记首个致死 Miss/Bad 出现的时间戳，提取其前驱 500ms 内的主导技法标签与拓扑特征。

4. **应变-误差响应模型与段位映射器 (Strain-Error Response Engine)**：
   - 将对局中每次敲击的真实绝对时间与 `proj7k.strain` 生成的 8 维瞬时应变曲线 $S_d(t)$ 对齐；
   - 沿应变离散区间（Bins）统计玩家击键误差标准差曲线与漏键密度分布；
   - 采用 Sigmoid / 双曲正切阈值拟合，提取性能发生突变恶化的临界拐点作为“有效承压上限”；
   - 对接段位权威层级阶梯（Canonical Dan Progression Hierarchy）将承压上限映射为对应的 8 维技法段位评级。

5. **宏观画像聚合器与轻量持久化 (Macro Profile & Persistence)**：
   - 基于 SQLite 存储玩家历史对局摘要快照（时间、MD5、8 维承压、UR、致死点）；
   - 提供近 30 天滑动窗口（Recent Rolling Form）聚合与历史巅峰（All-time Peak Profile）计算；
   - 执行过滤逻辑：跳过有效击键时间 $<30$ 秒或音符完成度 $<50\%$ 的弃赛局，对中途暴毙局保留致死前高应变样本。

6. **推荐与闭环联动引擎 (Recommendation & Downscaler Pipeline)**：
   - 根据短板突破（Bottleneck Breaker）或长板专精（Specialty Push）策略挑选目标技法与段位区间；
   - 扫描本地 Realm 数据库中已注入的技法星级桶标签（Binned Skill Tags）匹配候选曲目；
   - 提取致死段落 $[t_{\text{fatal}} - 10000\text{ms}, t_{\text{fatal}} + 5000\text{ms}]$，切出局部高能切片并调用 `proj7k.downscaler` 生成 Recovery、Bridge、Push 三阶梯练习包。

7. **顶层测试与调用统一接缝 (Unified Top-Level Seam)**：
   - 对外暴露统领接口与 CLI 入口：接收请求参数，返回完整结构化的诊断结果对象，支持终端排版与 JSON 序列化，驱动本地 CLI 与 Live Web 仪表盘。

## Testing Decisions

1. **纯外部黑盒行为测试原则**：
   - 仅测试最高层集成接缝（`run_profiler` / CLI 入口），绝对不单测内部私有数学拟合小函数；
   - 输入使用构造的合成 `.osr` 回放文件或真实测试切片与对应 `.osu` 谱面；
   - 验证输出数据结构中病理特征（UR、左右手偏载、漂移斜率、鬼键数）、承压上限段位映射、以及持久化数据库状态。
2. **测试模块范畴**：
   - `test_profiler_ingestion`：因果时序匹配、判定消费、漏键与惊慌鬼键隔离；
   - `test_profiler_pathology`：各轨 UR 差异、连叠疲劳漂移线性斜率、LN 释放偏置计算；
   - `test_profiler_response`：瞬时应变点对点对齐、有效承压上限拐点拟合与 Jinjin 段位映射；
   - `test_profiler_macro_aggregate`：30 天滚动状态与巅峰画像计算、Retry 局过滤规则；
   - `test_profiler_closed_loop_cli`：CLI 端到端执行、三阶梯练习包派生联动与本地曲库召回。
3. **既有参考基准 (Prior Art)**：
   - 参照 `test_downscaler_cli.py` 与 `test_downscale_engine.py` 的测试夹具构造规范；
   - 参照 `test_lazer_sync_e2e.py` 的 SQLite / Realm 临时目录隔离与上下文验证方案。

## Out of Scope

1. **修改或反向影响铺面固有难度**：严格遵守 [ADR-0001](file:///Users/kz/proj7k/docs/adr/0001-decouple-intrinsic-difficulty-from-player-data.md)，玩家回放表现数据绝不参与固有星级评定。
2. **段位考级曲目直接推荐**：严禁直接推荐 Jinjin Dan 官方考题，杜绝应试背谱。
3. **云端集中曲库检索**：全网谱面集中爬取与云端 Web API 检索留待 Phase 3 云端平台开发阶段实现，本阶段优先本地已装曲库召回。
4. **键盘驱动级高频（1000Hz+）采样**：暂不侵入底层硬件驱动，仅以 `.osr` 动作帧为输入基准。
